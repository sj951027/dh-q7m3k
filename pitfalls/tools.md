# pitfalls/tools.md — 도구·git·배치·배포

**읽을 때**: 배치를 확인하거나 git·페이지 배포·텔레그램·DB 쓰기를 다룰 때. `PITFALLS.md`(매 세션 읽는 한 장)의 상세다 — 한 줄 = 함정 · 증상 · 피하는 법 · 날짜. **실제로 당한 것만**. 새 함정은 맨 아래에 덧붙이고, 어느 세션에서나 걸릴 수 있으면 `PITFALLS.md` '항상'에도 짧은 한 줄. 더는 안 일어나는 줄은 지운다.

## 2026-11-27 에 `PITFALLS.md` 에서 옮긴 줄 (글자 그대로)
- **콘솔 cp949 · heredoc · `taskkill /IM python.exe`** 는 `CLAUDE.md` 실행 주의로 승격(11/13) — 한글 출력은 `python -X utf8`, 스크립트는 Write 도구로 파일부터.
- **`leaderboard.py` 를 점검용으로 돌리면 `docs/leaderboard*.json` 을 덮어쓴다** → `lb.model_ic` 를 직접 불러 계산, 돌렸으면 `git checkout -- docs/`. 9/13.
- **`git diff --stat` 줄바꿈 착시**: CRLF/LF 차이로 수백 줄처럼 보임 → `git diff -c core.autocrlf=false` 로 실제 diff 확인, 줄바꿈만 바뀐 파일은 커밋 안 함. 11/8.
- **커밋에서 빼는 것**: `panel.pkl`(153MB) · `docs/`(배치가 push). `research/large_verdict_status.md` 는 배치가 매일 다시 써서 늘 변경으로 뜬다(무해).
- **배치가 다시 만드는 `docs/` 페이지(index·_large_obs 등)는 산출물만 고치면 그날 밤 되돌아간다** → 생성 코드(`build_*.py`)의 문구를 고친다. 11/13.
- **텔레그램·DB 쓰기**는 드라이런으로만 확인, 실제 발송은 배치에.
- **페이지 배포 "Found 0 artifact(s)"는 다시 눌러도 안 된다**(11/24~25) → 올리기 뒤 대기 단계(`deploy-pages.yml`). 텔레그램 "이상 없음"은 배포 성공을 뜻하지 않는다. 11/25.
