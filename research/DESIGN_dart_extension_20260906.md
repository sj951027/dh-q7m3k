# DART 수집 확장 설계 — 실적 발표 캘린더·잠정실적·공급계약 (2026-09-06, 설계만 · 코드 미적용)

> 대상 과제: LARGE_SCORE_DESIGN 대기 과제 "DART 실적 발표일 캘린더 수집(판정 시즌 후)" +
> 사용자 우려("이벤트 신호는 우연성") 에 대한 답 — **실적 발표는 모든 종목에 분기마다 오는 루틴 이벤트**라
> 자사주·공급계약 같은 '우연한' 이벤트와 성격이 다르다. 그래도 점수식 편입은 아니고 **관측(가중 0) 적재 → h20/h60 검증** 경로.
> 웹 조사 출처는 문서 끝. 아래 수치 중 '문헌' 표기는 남의 실측이고 본 프로젝트에서 **미실측**이다.

## 0. 쉬운 설명

- 지금 `dart_events` 는 '주요사항보고(B)'만 모은다(유상증자·CB·자사주…, 2023-06~ 15,442건+).
- 실적 관련 공시는 다른 서랍(A 정기공시, I 거래소공시)에 있어서 지금은 하나도 없다.
- 제안: 같은 수집기에 서랍 2개(A, I)를 더 열어 **실적 발표일**과 **잠정실적 공시일**을 모은다.
  숫자는 안 읽는다(문서 파싱 없음) — **발표일 + 그날 주가 반응**만으로 '어닝 서프라이즈'를 대신 잰다.
- 검증은 3년 가격 DB로 "발표일 반응 상위 20%가 그 뒤 20·60일 더 가는가"(PEAD)를 본다. 통과 못 하면 캘린더만 남긴다.

## 1. 무엇을 모으나 (opendart `list.json`, 기존 배관 그대로)

| 그룹 | pblntf_ty / detail | report_nm 패턴 | event_type | 용도 |
|---|---|---|---|---|
| 정기공시 | A / A001·A002·A003 | `사업보고서`·`반기보고서`·`분기보고서` | `periodic_report` | 실적 확정 공시일 캘린더(PIT 재무 기준일 검증·이벤트 창 회피) |
| 거래소 공정공시 | I / I002 | `영업(잠정)실적(공정공시)`·`연결재무제표기준영업(잠정)실적` | `earn_prelim` | **PEAD 앵커일**(대형주 대부분 여기서 첫 공개) |
| 거래소 수시공시 | I / I001 | `매출액또는손익구조30%` | `earn_change30` | 코스닥 중소형 실적 급변 첫 공개(의무 공시) |
| 거래소 수시공시 | I / I001 | `단일판매ㆍ공급계약체결` | `supply_contract` | 관측 전용(문헌 근거 약함 — 우연 이벤트, 낮은 우선순위) |
| 거래소 수시공시 | I / I001 | `주식소각결정`·`자기주식취득신탁계약체결` | `retire_x` / `buyback_trust` | 기존 B 그룹 자사주와 합쳐 '주주환원' 이벤트 완성(교차검증 갭 보완) |

- **넣지 않는 것**: D002 임원·주요주주 소유상황보고(내부자). 이유는 catalyst_insider.py 주석과 같다 — 목록만으로는
  사유(장내매수/무상증자/상속/스톡옵션) 구분이 안 되고, 사유는 문서 본문 파싱(document.xml)이 필요해 비용이 크다.
  프로젝트 불변 규칙 "내부자 elestock OFF" 유지. 문헌(한국거래소 내부자 정보비대칭 연구)은 있지만 정제 불가 상태로는 안 쓴다.
- **호출량 추정**: I 그룹은 일 수백 건 → page_count 100 기준 하루 5~10페이지. 3년 소급 ≈ 800일 × ~8 = **6~7천 호출**
  (일 한도 20,000 안, 0.25s 간격이면 ~30분). 증분은 하루 10~20 호출. A 그룹은 분기 말 집중, 미미.
- **스키마 변경 없음**: `dart_events` 에 event_type 값만 늘어남. PK(rcept_no) 그대로. 표시·점수·판정 무연결(0-diff by construction).
- 증분 워터마크 주의: 현재 `MAX(rcept_dt)` 하나를 공유하므로 새 그룹은 **`--backfill 20230601 --groups A,I` 1회** 필요.

## 2. 검증 설계 (research/, 가중 0 — 통과 전엔 어디에도 안 붙임)

**가설 H1 (PEAD, 루틴 이벤트)**: `earn_prelim`/`earn_change30` 공시일(t0)의 **발표일 초과수익(EAR = t0~t0+1 종목수익 − 시장)** 상위 20%는
그 뒤 h20·h60 초과가 양(+), 하위 20%는 음(−).
- 잣대: 유니버스 중앙값 대비 초과, 진입 t0+2 종가(공시 다음날 매수 가정), 주블록 부트스트랩 CI, 국면(2024·2025·2026상·2026하) 병기.
- 문헌 참고(본 프로젝트 미실측): 한국 2000~2012, 양(+) 서프라이즈 60거래일 CAR **+3.5%**(t 4.5), 음(−)은 20일 **−1.6%**;
  드리프트는 **개인이 실적과 반대로 매매한 종목에서만** 존재. → 우리 `daily_flows.person_net_val`(t0~t0+2)로 이 조건을 그대로 재현 가능.
- 채택 문턱: h20 diff(상위−하위) CI>0 **그리고** h60 재현 **그리고** 3국면 중 2 이상 양(+). 통과 시에도 점수식이 아니라
  **표시 배지('📈 실적 후 n일')·운영 참고**부터. 모델화는 새 model_id + PREREGISTER.

**가설 H2 (실적 발표 회피 창)**: 저변동(lv_b) 픽 중 보유 40일 안에 `periodic_report`/`earn_prelim` 이 있는 종목과 없는 종목의
40일 초과 차이. 차이 없으면 "실적 발표는 신경 안 써도 됨"이 결론(그것도 유용).

**가설 H3 (주주환원 완성)**: B 그룹 buyback + I 그룹 buyback_trust/retire_x 합산 이벤트 포트 — 9/05 실측(자사주 CAGR 13%·MDD −26%)이
신탁·소각을 더하면 유지되는지. 우선순위 낮음.

## 3. 구현 스케치 (dart_events.py, 추가만 — 패치는 승인 후)

```
GROUP_PATTERNS = {
  "B": EVENT_PATTERNS,                       # 기존 그대로
  "A": [("사업보고서","periodic_report"), ("반기보고서","periodic_report"), ("분기보고서","periodic_report")],
  "I": [("영업\(?잠정\)?실적", "earn_prelim"), ("매출액또는손익구조", "earn_change30"),
        ("단일판매.{0,3}공급계약", "supply_contract"), ("주식소각", "retire_x"),
        ("자기주식취득\s*신탁계약\s*체결", "buyback_trust")],
}
collect(con, key, bgn, end, groups=("B",))   # 기본 B 만 → 기존 동작 0-diff
main(): --groups B,A,I (기본 B) · 증분 실행 시 .bat 는 --groups B,A,I 로 바꾸되 첫 1회 --backfill 필요
```
- 오프라인 테스트(가짜 응답): 그룹별 분류·`[기재정정]` 별도 행·비상장 제외·기존 B 결과 바이트 동일.
- 실행은 사용자(네트워크). 소급 후 `SELECT event_type, COUNT(*), MIN(rcept_dt), MAX(rcept_dt)` 로 보고.

## 4. 우선순위·시점

1. **판정 시즌 후**(px_a 10월 초 이후) 적용 — 프로젝트 대기 과제 명시 시점 그대로. 지금은 설계만.
2. 적용 순서: A+I 수집(소급 1회) → H2(회피 창, 가장 싸고 운영 직결) → H1(PEAD) → H3.
3. 기대 이득(추정): H1이 문헌대로면 h60 +3%p 급 — 조용함 축(h20 IC≈0.18)과 **독립 정보**(실적 뉴스)라 결합 기여 가능성.
   단 "좋은 팩터 ≠ 좋은 추가 성분"(8/12) — 결합은 별도 검증.
