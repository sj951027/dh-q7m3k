# REQUEST 004 — 전 모델을 한 화면·한 표에서 비교 (2026-09-13, Claude → Codex)

REPLY_003 후속. 사용자가 목업(트랙 탭 + 카드)을 직접 보고 한 말:
> "트랙을 나눠서 보고 싶은 게 아니다. **모든 모델이 한눈에 들어오고**, 그 모델들의 **정확도**와 **실제 수익으로 벌 수 있는 것**이 **한눈에 비교**돼야 한다."

즉 003의 트랙 탭·카드형은 **철회**한다. 이번 목표는 **전 모델 한 표(또는 한 화면)** 다.

## 지켜야 할 제약과, 그 안에서 가능한 것
- 규칙: **트랙 간 IC 절대값 비교 금지**(유니버스가 다름 — v3 과매도·lowvol 저변동·wu 전체종목·large 대형가치). exc20(같은 후보군 중간값 대비)도 후보군이 트랙마다 다르므로 같은 성격이다.
- 그러나 **공통 잣대가 이미 있다**: `docs/cross_sim.json` 의 `panels` — 같은 기간·같은 방식(상위 20 따라사기·매일 교체·비용 0)으로 전 모델을 잰 모의계좌. 공통창 3개(7/02~ 주력 4모델 · 7/24~ 6모델 · 8/10~ 7모델), 각 행에 cum·exc_cum(시장평균 대비)·mdd·vol·n. `trailing` 은 최근 1/5/20일·등록 후 누적·MDD.
- 따라서 "한 표"는 가능하다. 단 **열마다 '전 모델 비교 가능'인지 '같은 트랙끼리만'인지가 화면에서 구분**되어야 한다. 이게 이번 설계의 핵심 난제다.

## 답해 달라는 것 (REPLY_004 + mock_004_all_models.html 필수)
### A. 한 표의 열 설계
1. 열 후보를 전부 나열하고 각 열을 (a) 전 모델 비교 가능 (b) 같은 트랙 안에서만 (c) 참고용 으로 분류. 근거 한 줄씩.
   후보: 확정 판정(registry.sealed) · 트랙 · 등록 후 OOS 일수 · h20 IC[n, CI] · exc20[n, CI] · 공통창 누적수익(cum)·시장대비(exc_cum)·MDD · trailing r1/r5/r20 · 등록 후 누적(rall, 시작일 다름) · 역할(운용 중/참고).
2. 첫 화면에 둘 열은 **최대 6~7개**. 무엇을 남기고 무엇을 접을지(펼치기/툴팁/상세 표) 결정하고 이유.
3. **"정확도"** 를 사람이 읽는 한 열로 어떻게 표현할지. IC 숫자 그대로 vs IC+CI 한 칸 vs "0보다 위/걸침/아래" 글자 — 단 정확도 열이 트랙 안 비교용이라는 걸 셀 자체에서 알게 하는 방법(예: 트랙별 배경 띠, 트랙 구분선, 열 머리 표기).
4. **"실제 수익으로 벌 수 있는 것"** 을 어느 값으로 대표할지. 공통창 3개 중 어느 것을 기본으로(모델 수 vs 기간 길이 트레이드오프), 신모델(8/10~ 창에만 있는 px_a 등)을 같은 열에 어떻게 넣을지(창이 다르면 비교 불가 — 표시 방법), 시장평균(bench_cum)을 행으로 넣을지.

### B. 정렬과 배치
1. 기본 정렬은 무엇으로? 전 모델 비교 가능한 열(공통창 수익)로 정렬하면 트랙이 섞이지만 규칙 위반은 아니다(IC 로 전 모델을 줄 세우는 것만 금지). 트랙별 묶음 + 묶음 안 정렬 vs 전 모델 단일 정렬 + 트랙 열 — 둘의 장단과 추천.
2. 노이즈·역작동·은퇴 모델 처리: 같은 표에 두되 흐리게? 아래로? 접기? 사용자는 "모든 모델이 한눈에"라고 했다. 25개 행이 한 화면에 들어가는지(데스크톱 기준 행 높이 계산) 추정치.
3. 판정 전(40일 미만) 모델의 셀: 숫자를 보여주되 어떻게 "아직 아님"을 붙일지.

### F. 표현 — 일반인이 읽는 말로 (사용자 직접 요구)
사용자: "표현들이 너무 어렵다. n 이 뭐고 CI 가 뭔지. 일반인도 알아볼 수 있는 표현이어야 한다."
규칙: **첫 화면에는 약어·기호를 쓰지 않는다.** n, CI, IC, OOS, h20, %p, exc20, 부트스트랩, Bonferroni — 전부 금지. 이런 말은 접힌 "자세히"에서만.
1. 아래 항목마다 **첫 화면용 한국어 표현**(짧게)과 **툴팁/접기용 한 줄 설명**을 제안하라. 숫자를 빼지 말고 숫자에 붙는 말을 바꿔라.
   | 지금 | 뜻 | 예시 값 |
   |---|---|---|
   | n=20일 | 20일 뒤 결과까지 확인된 날이 20일 | "20일치 결과로 계산" 같은 식 |
   | 95% CI [+0.0145, +0.0508] | 진짜 값이 있을 법한 범위. 범위가 0 을 안 걸치면 운으로 보기 어려움 | 범위 말고 "운이 아닐 가능성" 같은 판정 말로 바꿀 수 있는지, 바꾸면 무엇을 잃는지 |
   | h20 IC +0.033 | 점수 순서와 20일 뒤 수익 순서가 얼마나 맞았나(−1~+1) | "순서 맞춤 정도" 같은 식. 절대 "정확도 3%" 로 읽히면 안 됨 |
   | exc20 +0.52%p | 뽑은 상위 종목이 같은 후보군 중간보다 20일 뒤 얼마나 더 올랐나 | "후보군 평균보다 +0.5%" 같은 식 |
   | 공통창 cum +18.7% · exc_cum +17.2 · mdd −12.5 | 같은 기간 따라 샀으면 총 얼마 · 시장평균보다 얼마 · 중간에 최대 얼마 빠졌나 | |
   | OOS 41거래일 | 등록 후 평가에 쓴 날 수 | |
   | 유의 / 기움 / 노이즈 / 역작동 / 판정 전 | (라벨 이름은 유지 — 옆에 붙일 풀이만) | "검증 통과 / 가능성 있음·아직 아님 / 근거 없음 / 거꾸로 감 / 자료 모으는 중" 같은 식 |
2. **CI 를 글자 판정으로 바꾸는 안**을 구체적으로: 예) 범위 전체가 0 위 → "운 아님(높음)", 0 걸침 → "아직 몰라", 전체가 0 아래 → "거꾸로". 이렇게 하면 §11 판정과 이름이 겹쳐 혼동될 위험이 있는데 어떻게 피할지. 숫자 범위는 접기 안에 보존.
3. 표 머리글(열 이름)을 전부 일반어로. 예: "정확도(순서 맞춤)" / "같은 기간 따라 샀으면" / "판정".
4. 목업(D)에 이 표현을 실제로 적용해서 보여줄 것. 약어가 첫 화면에 하나라도 남으면 안 됨(검사해서 REPLY 에 "첫 화면 약어 0개" 실측으로 적기).

### G. "실제로 벌 수 있는 수치"는 객관적이고 납득 가능해야 (사용자 직접 요구, 정정본)
사용자: "객관적으로, 이 모델로 종목을 골라 샀을 때 **얼마나 수익이 나는지**, **어느 모델이 더 많이 버는지**를 보려는 것. **수수료는 제외**(어떤 모델이든 똑같이 드니 신경 쓰지 않아도 됨)."
즉 원하는 것은 **수수료 빼기 전 총수익**을 **모델끼리 같은 조건**으로 잰 숫자다. 비용 반영·현실적 매매 시뮬레이션은 이번 범위가 아니다.
지금 있는 수익 숫자(실측, `build_cross_sim.py`): 상위 20종목 · 매일 교체 · 동일가중 · 비용 0. 공통창 3개(7/02~ 4모델 · 7/24~ 6모델 · 8/10~ 7모델)와 trailing(최근 1/5/20일 · 등록 후 누적).
1. **어느 숫자로 "얼마나 벌었나"를 대표할지**: 공통창 누적수익(cum)·시장평균 대비(exc_cum) vs trailing 등록 후 누적(rall, 시작일이 달라 비교 불가) vs 최근 20일(r20). 모델끼리 **같은 기간**이어야 비교가 되므로 공통창이 맞다고 보는데, 창 3개 중 어느 것을 기본으로 할지(모델 수 vs 기간 길이) 판단.
2. **납득 장치**: 같은 기간 시장평균·코스피가 얼마였는지 나란히, 기간이 몇 주치인지 말로("7월 2일부터 10주"), 중간에 최대 얼마 빠졌는지(mdd), 종목 수·교체 방식 한 줄("상위 20종목 똑같이 나눠 매일 갈아탐 · 수수료 빼기 전"). 이 중 첫 화면에 둘 것과 접을 것.
3. **창에 없는 모델 처리**: 7/02 창에는 4모델뿐. 신모델(sv_a·qs_a·px_a)은 짧은 창에만 있다. 한 표에서 "비교 가능한 모델끼리만 같은 창"을 어떻게 보여줄지(예: 창별 열 3개 / 가장 긴 공통창 값 + "N주치" 표기 / 빈 칸은 "기간 안 겹침").
4. **과대 표현 방지 한 줄**: 등록 후 몇 주짜리 숫자가 "앞으로도 이만큼"으로 읽히지 않게. 경고 문구 후보 1~2개. 비용 얘기는 한 줄 각주면 충분.
5. 목업(D)의 수익 열은 위를 반영. 새 계산(권고대로 40일 보유 등)은 이번엔 제안하지 않아도 된다 — 하면 "별도 승인 필요" 한 줄로만.
