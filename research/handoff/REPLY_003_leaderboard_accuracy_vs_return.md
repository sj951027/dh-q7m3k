### 3. 한 모델 설명의 정확한 틀

긴 한 문장 대신 다음 네 줄을 고정 순서로 사용한다.

> **[모델] · 확정 판정 [라벨·판정일]** [운용 중/참고, 해당할 때만]
>
> 예측: 전체 후보 순위 IC [값] · 채점 완료 n=[일] · 95% CI [하단, 상단].
>
> 상대 수익: 진입 후 20거래일, 같은 후보군 중간값 대비 [값]%p · n=[일] · 95% CI [하단, 상단].
>
> 따라사기: [기준일]까지 최근 20거래일 [값]% · 해당 기간 n 미제공 · CI 없음 · 관측 기록, 판정과 무관.

각 CI 뒤에 붙이는 해석은 **그 지표만** 설명한다: ‘95% CI가 0보다 위/아래’ 또는 ‘0을 걸침·양음 구분 어려움’. ‘우연 아님’이나 IC 해석을 수익 문장 뒤에 이어 붙이지 않는다. ‘IC 양수 비율’을 승률로 번역하지 않고 첫 카드에서는 생략한다.

**실측 예시 — sv_a**

- 확정: 기움(9/13), 채택 아님.
- 예측 IC **+0.0330**, n=20, 95% CI **[+0.0145, +0.0508]**. 이 IC의 구간은 0 위다.
- 20거래일 상대 수익 **+0.52%p**, n=20, 95% CI **[−0.01, +1.14]**. 이 수익의 구간은 0을 걸친다.
- 최근 20거래일 따라사기 **+6.7%**, 09/10 기준, 해당 기간 n 미제공·CI 없음·관측 기록. 전체 이력 n=40은 이 기간 n 대신 쓰지 않는다.

**실측 예시 — le_a**

- 확정: 노이즈(9/13).
- 예측 IC **−0.0145**, n=20, 95% CI **[−0.0427, +0.0150]**.
- 20거래일 상대 수익 **+4.45%p**, n=20, 95% CI **[+2.49, +6.62]**.
- trailing에 le_a 기록이 없어 최근 따라사기 수익·기간 n·CI는 미제공이다. exc20을 최근 계좌 수익으로 대체하지 않는다.

두 사례는 ‘전체 순위의 예측’과 ‘상위 종목의 상대 수익’을 나누어 봐야 하는 이유다. 예측력이 음수라고 상대 수익도 음수로 바꾸어 설명하거나, 초과수익이 양수라고 노이즈 판정을 승격하지 않는다.

## B. CI 없는 수익 표시 — 두 안

REQUEST 003은 **없으면 없다고 표시하는 수익 노출을 명시적으로 허용**했다. 002의 숨김 기본안을 이번 요청에 그대로 적용하지 않는다. CI를 새로 계산하지 않는다.

| 항목 | 안1: 바로 표시 — 추천 | 안2: 상세에서만 |
|---|---|---|
| 첫 카드 | 예측·초과수익 밑에 점선 배경의 ‘따라사기 관측 기록’ 구역 | 예측·초과수익까지만, ‘따라사기 기록 보기 · CI 없음’ 펼침 버튼 |
| n·CI 표시 | r20 바로 밑 ‘이 기간 n 미제공 · CI 없음 · 판정과 무관’ | 상세를 펼치면 동일한 라벨과 값 |
| r1·r5·누적 | r1/r5 각각 기간 n 미제공·CI 없음, 누적은 전체 n와 시작일·CI 없음 | 같은 정보가 상세 안에 있음 |
| 장점 | 실제로 얼마 벌었는지 바로 비교. 노이즈 모델의 좋은 기록도 사실대로 드러남 | 본 화면 정보량과 관측 수익의 시각적 비중이 줄어듦 |
| 잃는 것·위험 | 큰 수익률에 시선이 쏠릴 수 있어 판정 배지·관측 라벨을 항상 함께 보여야 함 | 사용자가 찾는 수익을 매번 펼쳐야 함. 수익순 정렬 시 왜 그 순서인지 처음에는 안 보임 |

**안1 추천 이유**: 사용자는 예측과 수익 모두 보고 싶어 한다. 불확실성을 누락하지 않고 기록의 성격을 명시하면, 수익을 숨기지 않으면서 판단 근거를 분리할 수 있다. 이것이 수익의 확실성을 새로 증명하는 것은 아니다.

목업에서는 상단 라디오로 두 안을 전환한다. 안2에서도 최근 수익순 정렬은 선택할 수 있지만 순서를 설명하는 값은 상세에만 있어 비교가 느려진다. 이 손실을 두 안의 실제 차이로 남겼다. 토글은 CSS로 표시만 바꾸며 수치·정렬·판정은 바꾸지 않는다.

`trailing.n`은 등록 후 전체 기록일 수다. r1/r5/r20 각각의 유효 표본 수로 전용하지 않는다. ‘최근 20거래일’은 창 이름이며 확인된 n=20이라고 표시하지 않는다. 모든 수익 구역에서 비용 0·매일 교체하는 모의 기록이라는 조건을 밝힌다. 실제 사용자의 40일 보유 계좌 수익과 같다고 표현하지 않는다.

## C. 디자인과 목업

### 색과 아이콘

- 수익의 +는 파랑, −는 주황. 부호·단위를 항상 함께 표시한다. IC는 중립 글자색이다.
- 확정 판정은 수익색과 다른 체계: 유의는 보라 계열, 기움은 황색 계열, 노이즈·판정 전·은퇴는 중립 배경과 **서로 다른 텍스트**다. 색만으로 구별하지 않는다.
- ●●●는 제거한다. 신뢰 등급처럼 보이지만 모든 판정 조건을 나타내지 못한다. ★는 ‘운용 중/참고’ 작은 글자 배지로 대체한다. 🏆·🪦도 ‘확정 판정/은퇴·기록’ 텍스트로 대체한다.
- 판정 전 자동 노이즈는 ‘판정 전·자료 수집 중’, 판정 완료 노이즈는 ‘확정: 노이즈’, 은퇴는 ‘은퇴·기록 / 적재 중지’로 구분한다. 자동 라벨은 상세에서만 그대로 보여 준다. 확정 노이즈의 재판정은 원칙과 VERDICT 예외를 따른다.

### 제목 후보

1. **모델의 예측과 수익** — 추천. 사용자 질문 두 개를 그대로 제목으로 쓴다.
2. 모델 성적과 판정 — 짧고 기록의 성격을 강조한다.
3. 트랙별 모델 관측표 — 비교 범위를 분명히 하지만 조금 더 딱딱하다.

‘리더보드’는 단일 종합 순위가 있다는 기대를 만든다. 트랙별·축별 관측값 정렬만 제공하는 이번 화면에는 위 제목이 더 적합하다.

### 반응형 배치

- 1000px 이상을 포함한 넓은 화면: 최대 내용 폭 1120px, 카드 안 예측·수익 두 열.
- 700px 이하(390px 포함): 같은 카드가 예측→수익 한 열로 전환. 가로 표·고정 최소 너비를 없앴다. 상태는 모델명 아래로 흐르고 필터는 줄바꿈한다. 내용은 CSS만으로 반응하며 창 너비를 읽는 JavaScript는 없다.

**실측한 스크립트 동작**(브라우저 대신 최소 DOM 대체 객체로 검사):

1. 실제 브라우저 화면은 정책 차단으로 미검증이다. 목업을 열어 390px과 1000px 이상에서 글자 겹침·가로 넘침, 두 표시안 토글·트랙 선택·상세 펼침을 직접 확인할 필요가 있다.
2. REQUEST의 ‘ls_t1이 맨 위’는 현재 로컬 코드·JSON과 정확히 일치하지 않는다. active의 exc20순에서는 lv_b(+2.20%p, n=32, CI [+0.64,+3.79])와 v30(+2.01%p, n=45, CI [+1.13,+2.88])이 ls_t1(+1.93%p, n=5, CI [+0.87,+2.96])보다 위다. **전 트랙 IC순 상세에서는 ls_t1이 위**다. 이는 제안의 이유인 트랙 혼합 문제를 없애지는 않으며, 수치 정렬 확인만 구분한다.
3. leaderboard 자체 기준일이 없고 cross_sim은 09/10, registry는 09/13이다. 목업은 각각 표시하며 새 기준일을 추정하지 않는다. 최신 웹 배포본과의 동기화는 검사하지 않았다.
