## 3. 장치 검토

[실측] 시작은 `git rev-parse HEAD`·상태 저장, 저장 함수는 오래된 파일 삭제도 한다(`tests/knowledge_guard.py:71–76,148–159`). 끝은 `git status`·저장을 한다(`43,179–201`). 배치의 add·commit·push는 `run_and_diversify.py:191–208`, hook의 `-B` 설정은 `.claude/settings.json:8,20`에 있다.
[제안] 시작을 그대로 켜지 말고 **문서 읽기·출력만 하는 경로**로 분리한다(상태 저장/삭제·git 생략, `-B` 유지). `rev-parse`는 커밋을 쓰지 않지만 배치와 동시에 읽은 자료의 시점은 어긋날 수 있다. 끝 검사는 계속 끈다. 종료 로그와 무관하게 22:30까지 제한은 불변이다. 이득은 경계 유지, 비용은 구현자의 쓰기 없는 경로 검사다.

[제안] **PreToolUse**의 단순 문자열 검사는 `rg 'taskkill /IM python.exe'`, 주석·echo·문서용 heredoc·`python script.py`·`/PID` 종료를 오탐한다. 실행 명령을 분해해 Python 입력의 heredoc과 taskkill의 `/IM python.exe`를 좁게 확인한다(옵션 순서·대소문자·인용·인식 가능한 중첩 셸 처리). 해석 불가를 안전으로 판정하지 않는다. 이득은 반복 사고 차단, 비용은 구현자의 위반/정상 명령 회귀 검사다. hook 호환성은 실행 확인하지 않았다.

[제안] **페이지 검사**는 모델×판정 창의 상태 표시를 registry와 대조한다. 생성기 표시 부분을 작은 가짜 registry로 메모리 렌더하고 미판정→완료 전환을 검사한다(`main()`·배치·DB 쓰기 없이). 전체 HTML 비교나 ‘검증 전’ 전역 금지는 다른 모델·돈 잣대·후속 창을 오탐한다. 수급 일정처럼 registry 밖의 문구만 좁은 금지 목록으로 보완한다. 이득은 자동 갱신, 비용은 구현자의 생성기별 연결과 의미 변경 때 검사 수정이다.
[실측] `build_large_report.py:406` 외에 `407`에도 ‘60일 적재 후(8월 말)’가 남아 있다. registry에는 이 수급 구현 상태가 없다.
