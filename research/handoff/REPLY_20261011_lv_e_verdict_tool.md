# lv_e 판정 숫자 도구 — 눈가림 제작·가짜 자료 검증

작성: 2026-10-11(KST). 산출물은 이 문서와 `code_20261011_lv_e_verdict_tool.py` 두 파일뿐이다.

## 범위와 직접 확인한 결과

- **실측:** 가짜 메모리 DB 7개 사례 모두 PASS. 추가로 선행 부트스트랩 루프와 수치 일치, 게이트·종목 차이·결손·반올림 경계를 검증했다. 아래 모든 상관·구간·방향 숫자는 **직접 만든 가짜 자료** 결과다.
- **실측:** 실제 DB는 `mode=ro`와 `query_only=ON`으로 열어 `PRAGMA table_info`의 열 이름만 확인했다. 실제 점수·가격·수익을 조회하거나 계산하지 않았다. **`--real` 실행 횟수 0.**
- 기존 점수·판정·게이트·`docs/` 수정, 수집기·배치 실행, DART·KIS·외부 호출, 커밋·푸시 없음. 사용자가 산출물을 두 파일로 한정했으므로 worklog와 patch_note는 추가하지 않았다. 작업 시작 때 이미 있던 수정·미추적 파일도 건드리지 않았다.
- 리더보드 화면·텔레그램 기록·루트 `VERDICT_202610*_v30*.md`는 열지 않았다. 필수 작업 기록과 지정 사전등록·8/29 판정 문서에는 과거 결과가 들어 있었으며 읽었다. **과거 결과까지 전혀 보지 않았다는 뜻의 완전한 눈가림은 아니다.** 현재 lv_e 실제 성과는 조회·재계산·출력하지 않았다.

## 사용법

저장소 루트에서 실행한다. Python 3.11.4, numpy 2.4.4, pandas 2.3.3 환경에서 검증했다. 표준 라이브러리 외 의존성은 numpy·pandas뿐이며, 저장소 모듈을 import하지 않는다.

```powershell
# 지금 허용된 검증. 옵션 생략도 같은 메모리 DB 검증이다.
python -B research/handoff/code_20261011_lv_e_verdict_tool.py --self-test

# 실제 DB의 열 이름만 확인. 점수·시세 값은 읽지 않는다.
python -B research/handoff/code_20261011_lv_e_verdict_tool.py --schema

# 판정 날에만 사용. 이번 작업에서는 실행하지 않았다.
python -B research/handoff/code_20261011_lv_e_verdict_tool.py --real

# 필요하면 판정 자료의 마지막 날짜를 명시한다.
python -B research/handoff/code_20261011_lv_e_verdict_tool.py --real --as-of YYYYMMDD
```

기본 DB 경로는 저장소 `history.db`와 자매 폴더 `../dh-q7m3k-data/ohlcv.db`다. 다른 위치는 `--history PATH --ohlcv PATH`로 지정한다. `--real`의 기본 마감은 시세표 마지막 날짜이며, 마감 이후 run·시세는 포함하지 않는다. 파일을 저장하지 않고 콘솔에 출력한다. 실제 DB 연결은 읽기 전용 트랜잭션이며 서로 다른 두 DB의 시점까지 원자적으로 일치시키는 장치는 아니다.

기본 실행과 `--self-test`에서는 `sqlite3.connect`를 감싸 **`:memory:` 이외 DB 연결을 차단**한다. 평일 20:10~22:30 KST에는 분석 전에 중단한다. 이 시간대에는 먼저 `skip_dates.txt`의 해당 날짜 유무만 확인하며, 명시된 날은 예외다. 도구를 금지 시간에 시작하지 않는 운영 규칙도 그대로 적용한다.

## 출력과 계산 정의

1. 어느 병기 게이트에서든 to20 커버리지 <90% 앵커가 있으면 출력 첫 줄은 **`보류 검토`**다. 앵커별 분자·분모·비율과 미달 앵커 수, 결측 **과반(>50%)** 앵커 수도 따로 낸다. 정확히 50% 결측은 과반이 아니지만 90% 조건에는 미달한다.
2. 유효 앵커 수와 가격 날짜 차 `N−1−등록일 위치`, 등록일 포함 가격 날짜 수, 등록 run 제외 앵커 수를 병기한다. 등록일은 20260901이며 기본 앵커 집계에는 당일을 포함한다. 미래 창 완결 수와 상관 산출 가능 앵커 수는 이 수와 구분한다.
3. 40일 정의별 충족 여부를 따로 출력한다. **둘 중 하나라도 40 미만이면 상태는 `중간 관측`, 해석·자동라벨 칸은 빈 문자열**이다. 정의가 엇갈린 날도 사용자 선택 전에는 합성 판정을 내리지 않는다. 이것을 새 사전등록 채택 조건으로 주장하지 않는다. 숫자는 계속 관측용으로 출력한다.
4. 성과 표보다 앞에 각 앵커의 lv_e·lv_b run, 종목 수, 공통 수, 각자만 있는 수, 집합 동일 여부를 출력한다. 집합 단위는 `(market,ticker)`다.
5. h20·h10 모두 시장별 상관, 유효 시장 상관의 동등가중 평균, 전 유니버스 통합 상관을 낸다. 점수는 저장된 `lowvol_score`를 그대로 읽으며 다시 만들지 않는다. 평가 집합에서 평균 동점 순위로 Spearman을 계산한다. 종목쌍 8개 이상, 점수·수익 각각 고유값 3개 이상을 요구한다.
6. 단순 수익은 `C[t+1+h]/C[t+1]−1`. `daily_ohlcv`만 사용한다. 보유구간 일변화 절대값 최대 >0.32는 제외한다. 선행 코드처럼 내부 결측을 건너뛴 최대값을 쓰며, 모든 변화가 비었거나 양 끝 가격이 없으면 빠진다. 보충표 합치기·수익 대체는 하지 않는다.
7. 날짜 단위 iid 95%·Bonferroni 구간, 달력 주 블록 95%·Bonferroni 구간은 **4,000회, seed 7**이다. 보정 분모는 요청대로 **11**, 꼬리는 `100×0.05/11/2`와 그 반대쪽 백분위다. DB distinct 모델 수도 나란히 표시하며, 불일치하면 검토 문구를 낸다. 은퇴 모델을 분모에서 빼지 않는다.
8. 주 블록은 주를 복원추출하여 그 주에 속한 **모든 앵커를 이어 평균**한다. 주 평균을 동등가중하는 방식이 아니다. 선행 코드와 같은 run 날짜의 월~일 주를 사용하고, 휴일 run 때문에 달라질 수 있는 **실제 앵커 날짜의 주 기준**도 병기한다. 방향은 앵커 IC>0 비율과 주 평균 IC>0 비율 둘 다 낸다.
9. 짝비교는 h20·h10 각각 **lv_e−lv_b**다. 각자 종목으로 먼저 만든 상관의 같은 앵커 차이와, 양쪽 점수·수익이 모두 유효한 같은 시장·종목 교집합에서 다시 순위를 매긴 차이를 병기한다. 각 차이에 iid·주 블록·보정 구간이 붙는다. 선행 도구처럼 공통 앵커 10 미만이면 차이 추정치는 비우고 n과 사유를 남긴다.
10. 시세 양 끝 결손, 검사할 일변화 없음, 점프컷, 내부 가격 구멍, 점수 결손, 유효/제외 쌍을 **모델×앵커×종목** 단위로 센다. 사유별 수는 중복될 수 있다. 미래 창 미완결과 최소 종목/고유값 부족은 가격 결손과 구분한다.

모든 문턱 비교는 반올림 전 값으로 한다. 구간·평균·비율은 출력할 때만 소수 여섯 자리로 표시한다. `0.000000`이 반드시 내부 값의 정확한 0을 뜻하지는 않는다.

## L1~L10 대응 — 어느 쪽을 주지표로 할지 선택하지 않음

| 항목 | 구현·표시 |
|---|---|
| L1 과매도 30/40 | 유지 run의 stage3 및 lv_e 각각 `[30,40)` 종목-날짜 관측 수와 고유 종목 수, lv_e의 stage3 연결 실패 수를 낸다. 미적재 점수를 만들어 대체 유니버스 성과를 계산하지 않는다. 그 수치는 **확인 못 함**. |
| L2 시장 평균/통합 | 같은 h·모델·종목 방식에서 시장 평균과 통합을 병기. 개별 시장 수치도 포함. |
| L3 40일/당일 포함 | 앵커 수·가격 날짜 차·포함 가격 날짜 수·등록 run 제외 앵커 수와 각 40 충족 여부 병기. 완결 h 표본 수는 별도. |
| L4 방향 | 앵커 방향과 주 평균 방향, 각각 60% 충족 여부 병기. |
| L5 실제 보정/고정 문턱 | 실제 α/11 구간과 기존 자동 라벨을 병기. 자동 라벨은 **2,000회·원시값의 참고**이며 승격 판정이 아니다. 0.02/0.03/−0.02 경계는 참고 라벨 재현에만 쓰며 새 골대로 채택하지 않는다. 기존 화면의 사전 반올림은 재현하지 않는다. |
| L6 h10·짝비교·주 블록 | h20·h10 단독/짝비교·주 블록 모두 산출. h10 평균 양수·95% 하단 양수·보정 하단 양수를 각각 표시하여 ‘재현’ 의미를 고르지 않는다. 짝비교도 평균>0과 95% 하단>0을 따로 표시한다. |
| L7 커버리지 90%/과반 | 두 조건을 따로 센다. 맨 위 보류 검토는 사용자가 지정한 <90% 조건으로 표시한다. |
| L8 30%/50%·stage1 없음 | **판정30**: stage1 중앙값 30% 미만 + 전 트랙 double. **적재50감도**: 50% 미만·stage1 run 없음 + 같은 double. **적재50원형**: 50% 미만·stage1 run 없음, double 별도 제거 없음. 세 결과를 나란히 낸다. 단계별 역할 차이를 숨기지 않도록 원형도 별도로 둔다. |
| L9 해석 빈칸 | 사전등록 §4의 커버리지 보류·h20 구간 0 포함(기움 이하)·짝비교 0 포함(기여 미확인)을 표시한다. 완전한 해석 조합표는 문서에서 찾지 못했다. **`해당 칸 없음, §11 기본값`**을 출력하고 자동 승격/역작동 처분 규칙을 만들지 않는다. |
| L10 반복·주·결손 | 선행 정본 4,000회와 자동 경로의 iid 2,000회 구간을 병기. seed 7, 월~일 주, 결손 상세를 명시. 주 경계가 run/실제 앵커에서 달라지는 경우도 병기한다. |

휴일 run은 최대 5일 전 가격 날짜에 매핑한다. 등록일 필터 후 거래일 run을 우선하고, 없으면 가장 이른 run을 유지한다. 20260910·20260911에 특별한 예외는 넣지 않는다. 각각 run 존재 수, 매핑 날짜, 유지/게이트 제외/중복·매핑 실패 사유를 출력한다. 9/10 run이 없으면 생성·보간·9/11로 합산하지 않는다. 9/11도 일반 규칙으로 처리한다. **이번 실제 DB에서 두 날짜의 현재 상태를 다시 세지는 않았다.**

추가 검증도 모두 통과했다.

- 선행 코드와 동일한 난수 루프로 iid95·Bonferroni 및 주 블록95를 독립 계산해 새 구현과 대조했다(절대 허용 오차 1e−15).
- 원시 CI 하단 0.019999999와 0.020000001을 서로 다르게 처리했다. 출력 반올림이 비교에 들어가지 않는다.
- 종목 수가 다른 두 모델에서 한쪽 순위를 뒤집어 이론상 짝차이 **2**를 만들고 h20·h10, 각자·교집합, 시장 평균·통합 모두 확인했다.
- 가짜 stage1의 37.5% run은 30% 경로에 남고 50% 경로에서 빠졌다. stage1 없는 run, 모델 내부 61분 시간차의 double, 거래일/주말 중복 run도 확인했다.
- 양 끝 가격 결손, 고유 수익값 부족, 종목 수 부족, >32% 점프, h20 미래 창 미완결을 확인했다.
- to20은 관측 한 개로 산출되며, 그 관측이 20일 격자 밖으로 나가면 결측이 되고, 다음 날 관측을 미리 끌어오지 않음을 확인했다.
- 가짜 9/10 run을 지워 ‘run 없음’, 가짜 9/11은 ‘유지’ 출력으로 확인했다. 실제 두 날짜의 성과는 계산하지 않았다.

## 실제 표 구조와 맞춘 근거

실제 DB에서 직접 확인한 아래 열만 도구가 요구한다. `--schema` 전체 검사가 성공했다. 표 구조 일치는 실제 판정 수치의 일치를 입증하지 않는다.

| DB / 표 | 사용하는 실제 열 이름 | 용도 |
|---|---|---|
| history / lowvol_scores | `run_id, market, ticker, model_id, lowvol_score, spec_hash, frozen_at` | 동결점수·집합·double 판별. 원표의 `n_universe`도 존재하나 분모를 그 저장값으로 대체하지 않음 |
| history / stage1_oversold | `run_id` | run별 COUNT(*)와 전체 기간 중앙값의 30%/50% |
| history / stage3_final | `run_id, market, ticker, oversold_score` | `[30,40)` 집계 및 동결 유니버스 연결 |
| history / v3_scores | `run_id, model_id, frozen_at` | 공통 double 집합. v3 점수는 읽지 않음 |
| history / wu_scores | `run_id, model_id, frozen_at` | 공통 double 집합. wu 점수는 읽지 않음 |
| ohlcv / daily_ohlcv | `ticker, date, close, volume, shares` | 미래 수익·날짜 격자·to20 |

double은 각 모델 안의 동결시각 최대−최소가 60분 이상인 run의 전 트랙 합집합이다. 모델 사이의 백필 시간차를 double로 오인하지 않는다. 해석할 수 없는 동결시각 수도 별도로 출력한다. 필수 표·열 부재, 가격/점수/stage3 키 중복, stage1 완전성 기준 부재는 `확인 못 함`으로 중단한다. 조용히 새 대체 규칙을 적용하지 않는다.

## 못 맞춘 것·확인 못 함

- **실제 판정 결과·실제 자료로의 전체 실행은 확인 못 함.** 동일 입력 읽기·계산·출력 경로를 메모리 DB로만 검증했다. 실제 자료의 예상 밖 결손·형식과 실행 시간·메모리 사용량도 확인 못 함.
- **완전한 사전등록 해석표는 확인 못 함.** 특히 h10 재현의 정확한 문턱, h20/h10 짝우위의 결합, 주 블록만 실패했을 때 처분, 미정 조합의 최종 라벨을 임의로 만들지 않았다. 도구는 모든 기초 조건과 문서상 제한을 내며 채택 결정을 대신하지 않는다.
- **적재 당시 to20 커버리지는 확인 못 함.** `lowvol_scores`에 to20·결측 마스크가 동결돼 있지 않다. `volume/shares`를 전체 날짜 격자에 놓고 rolling(20,min_periods=1)로 현재 원천표 기준 커버리지를 재구성한다. 나중 백필·원천 수정·당시 수집 오류는 되돌릴 수 없다. 0인 shares는 결측, 0인 volume은 유효 값이다. run 날짜 exact join을 유지한다.
- to20 날짜 격자는 사전등록의 **전체 날짜 격자**를 명시적으로 보존한다. 생산 코드의 `pivot_table` 기본 동작은 전 종목 ratio가 결측인 날짜를 떨어뜨릴 수 있다. 그런 날짜가 실제로 있었는지와 당시 영향은 **확인 못 함**. 이 도구가 적재 당시 계산을 완전히 복원한다고 주장하지 않는다.
- **상류에서 누락된 30~40 후보의 점수와 성과는 확인 못 함.** 새 점수를 만들거나 기존 동결값을 바꾸지 않는다. 종목 수 각주만 낸다.
- **당시 stage1 및 stage3 원형 보존 여부는 확인 못 함.** 게이트·과매도 각주는 현재 표를 기준으로 한다. 적재50원형 경로도 이미 동결된 점수만 평가하므로, 적재에서 빠졌던 점수를 되살리는 실험이 아니다. stage1 표 자체가 없는 옛 환경의 stage3 폴백은 재현하지 않고 중단한다.
- 과거 코드에는 짝비교 공통 앵커 10 미만 추정 생략이 있다. 이 도구도 이를 따른다. 앵커가 40개 쌓여도 h20 완결·유효 상관 앵커는 훨씬 적을 수 있으며, 주 블록 수도 독립 표본 수를 보장하지 않는다.

## sv_b용으로 바꿀 때

| 부분 | 필요한 변경 |
|---|---|
| 모델/등록/입력 | `MODEL=sv_b`, `BASE=sv_a`, `REG=20260914`, `wu_scores.wu_score`로 변경. lowvol 과매도 각주는 제거하고 wu 가드 유니버스와 단일 점수 순위 구조를 확인해야 함 |
| 짝비교 | **sv_b−sv_a**, 같은 앵커 h20·h10, 각자/교집합 병기. `sv_a 우위 없으면` 문구의 주어 혼동을 새 규칙으로 해결하지 말고 차이 방향을 명시 |
| 보정 | sv_b 개별 사전등록 **분모 7** 및 wu distinct 수. lowvol의 11을 그대로 재사용하지 않음 |
| 커버리지 | to20 대신 `crb5=credit_bal_rate`의 rolling(5,min_periods=1), sv_b 평가 유니버스 대비 비율과 <90% 날짜를 계산 |
| 지연 | 신용 원천 관측일·사용 가능/적재 시점의 구분, 거래일 격자 기준 나이, **5거래일 초과**와 연속 구간을 별도로 출력해야 함. 현재 값만으로 당시 이용 가능 여부는 단정할 수 없음 |
| 보류의 ‘지속’ | 사전등록에 지속 일수의 명확한 정의가 없으므로 임의로 N일을 정하지 않음. 날짜별 위반·연속 길이를 내고, 최종 보류 결합표는 확인 못 함으로 남김 |
| 방향/계승 | sv_b는 주간 방향 기준 계보. 앵커 방향도 병기 가능하나 뜻을 바꾸지 않음. h10 재현·해석 빈칸·40일 정의·주 블록 한계는 다시 명시 |

이번 도구는 sv_b 실행 옵션을 제공하지 않는다. 위 변경은 다음 작업 범위이며 신용 원천표의 실제 열 구조·지연 데이터는 이번에 확인하지 않았다.

추가 파일·대형 중간 자료는 생성하지 않았다. 재현은 위 `--self-test` 한 명령이다.
