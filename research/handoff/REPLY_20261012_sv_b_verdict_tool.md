# sv_b 독립 판정 숫자 도구

작성·검증: 2026-10-11 KST. 파일명은 요청대로 20261012를 사용했다.

산출물은 이 보고서와 `code_20261012_sv_b_verdict_tool.py` 두 파일이다. 기존 lv_e 도구, 점수·판정·게이트 운영 코드, `docs/`, 작업 기록은 수정하지 않았다. 아래 성과 숫자는 전부 직접 만든 메모리 DB 자료의 검증값이다. **실제 자료 계산과 `--real` 실행은 0회**다.

## 사용법

저장소 루트에서 Python과 NumPy·pandas가 설치된 환경으로 실행한다. 저장소 모듈을 import하지 않으며 네트워크 호출이나 파일 저장 기능은 없다.

```powershell
# 기본값도 같은 가짜 메모리 DB 자체 검증이다.
python -B research/handoff/code_20261012_sv_b_verdict_tool.py --self-test

# 실제 DB에는 PRAGMA table_info만 실행한다.
python -B research/handoff/code_20261012_sv_b_verdict_tool.py --schema

# 아래는 판정 날 사용법이다. 이번 작업에서는 실행하지 않았다.
python -B research/handoff/code_20261012_sv_b_verdict_tool.py --real
python -B research/handoff/code_20261012_sv_b_verdict_tool.py --real --as-of YYYYMMDD
```

기본 경로는 저장소의 `history.db`, 형제 폴더 `dh-q7m3k-data/ohlcv.db`다. `--history`, `--ohlcv`로 바꿀 수 있다. 파일 DB는 `mode=ro`, `query_only=ON`과 읽기 트랜잭션으로 연다. 자체 검증은 `sqlite3.connect`를 감싸 `:memory:` 이외 접근을 차단한다. `-B`는 Python 캐시 파일 생성을 막는다.

평일 20:10~22:30 KST에는 종료한다. `skip_dates.txt`에 YYYYMMDD로 적힌 날과 주말은 예외다. 시작·통계·앵커 계산·자리바꿈 묶음 사이에서 시간을 재확인한다. 자리바꿈은 진행 상황을 stderr에 표시한다. 실제 자료 실행 시간과 메모리 사용량은 확인 못 함.

### 신용 커버리지·지연

`short_flows.credit_bal_rate`를 시세 본 표의 close 날짜 격자에 맞춘 뒤 `rolling(5, min_periods=1).mean()`으로 재구성한다. 커버리지는 **각 앵커의 sv_b 종목 중 crb5가 존재하는 수 / sv_b 종목 수**다. 원천 값 자체는 이월하지 않는다. 90% 미만 앵커가 하나라도 있으면 맨 위에 `보류 검토`와 그 앵커 수를 출력한다.

지연은 앵커 이후 자료를 쓰지 않고, 종목별 마지막 비NULL 자료일과 앵커 사이의 시세 거래일 위치 차로 센다. 유니버스 집계 방법이 명시되어 있지 않아 다음 두 값을 날짜별로 나란히 둔다.

- 가장 최근의 비NULL 자료일: 종목별 지연의 최솟값. 유니버스 전체가 늦어진 경우를 보여 준다.
- 가장 오래된 종목의 비NULL 자료일: 종목별 지연의 최댓값. 일부 종목만 늦어진 경우도 보여 준다.

각 날짜의 종목별 지연 빈도, 5일 초과 종목 수, 과거 실측이 전혀 없는 종목 수도 낸다. 실측 전무는 지연 0으로 바꾸지 않는다. 두 집계 각각 5일 초과 앵커 수, 연속 구간 목록과 최장 구간을 출력한다. 연속은 **가격 거래일이 이웃하는 관측 앵커**이며 run 없는 거래일·비초과·집계 불명은 구간을 끊는다. 일부 종목이라도 5일 초과면 `지연 검토`를 표시하되, ‘지속’을 몇 일로 정하거나 지연만으로 최종 보류를 자동 확정하지 않는다.

현재 DB로 재구성한 자료일 기준 진단이다. `fetched_at` 열이 있어도 동결 당시 자료 상태·수신 이력을 복원할 수 있다고 가정하지 않았다. **점수를 다시 만들거나 crb5로 덮지 않는다.** 10/06~08의 run 처리와 해당 날짜 신용 상태는 향후 실행 시 함께 출력된다.

### 각주 참고값 세 가지

`VERDICT_NOTE_20261011_power.md` 정의를 별도 경로로 구현했다. 참고값은 라벨·해석 함수에 사용하지 않는다.

1. h20·h10 완결 앵커를 시간순으로 보고 직전 선택 앵커보다 h거래일 이상 뒤인 것만 선택한 수·날짜. 상관 산출 가능한 앵커로 제한한 수도 별도 출력한다.
2. 두 모델 각각 연속 유지 run 공통 종목의 점수 순위 상관 평균, 같은 종목 비율 평균. 비율 분모는 앞 run 종목 수이며 run 쌍별 동일 가중이다. 수익을 사용하지 않는다. 거래일 간격이 1보다 긴 run 쌍도 연속 run에 포함하고 별도 계수한다.
3. **본 표·시장 평균·판정30에만** 자리바꿈을 붙인다. 두 모델의 창 안 출현 종목 합집합을 같은 시장 안에서 1:1로 섞고, 출현·결측을 포함한 전체 점수 흐름을 이동한다. 두 모델과 두 지평에 동일한 순열을 적용한다. 2,000회·seed 20261012. 시장 내 시총 5분위 감도도 실행한다.

자리바꿈 출력은 h20 sv_b 평균의 2.5·50·97.5 백분위, 실제 평균의 경험누적 백분위, 동점 중간 백분위, 양쪽 꼬리 비율과 +1 보정이다. 음수 실제값은 아래쪽 꼬리를 읽는다. h20·h10의 각자/교집합 짝차이 분포와 실제 차이 백분위도 출력한다. 동점 포함 경험누적과 동점 중간값의 정의가 다르므로, 전부 0인 차이 분포에서는 각각 100과 50이 된다.

‘유의’ 통계 조건 비율은 40일 조건·구간 하단>0·방향60%로 계산한다. 날짜95 / 주95 / 둘 다 / Bonf7 날짜·주·둘 다 / Bonf11 날짜·주·둘 다를 주 기준과 앵커 기준 각각 출력한다. h10 재현·짝우위·신용 보류까지 결합한 최종 승격 확률이라는 뜻은 아니다. 모든 시도가 비율 분모이며 상관을 낼 수 없는 시도는 통과하지 않는다.

시총은 창 안 첫 **양수이며 유한한 close×shares**다. 평균 동점 순위의 백분위로 시장별 5개 층을 만들며 시총 결측은 별도 6번째 층으로 남긴다. 층 크기·혼자 남는 종목·이름표 고정 비율도 출력한다. 뒤섞지 않은 연결이 주 계산과 앵커별로 같은지 매 실행 시 허용오차 1e-12로 검증한다.

## 실제 열 이름과 맞춘 근거

이번 실제 DB 접근은 `--schema` 한 번이며, 아래 표들에 **PRAGMA table_info만** 실행했다. 실제 점수·시세·신용 값이나 날짜·종목 수는 조회하지 않았다.

| DB / 표 | 도구가 사용하는 열 이름 — 실제 존재 확인 |
|---|---|
| history / wu_scores | `run_id`, `market`, `ticker`, `model_id`, `wu_score`, `frozen_at`, `spec_hash` |
| history / stage1_oversold | `run_id` — 완전성은 행 수로 계산 |
| history / v3_scores | `run_id`, `model_id`, `frozen_at` — 이중run 검사 전용 |
| history / lowvol_scores | `run_id`, `model_id`, `frozen_at` — 이중run 검사 전용, lowvol 점수 읽기 없음 |
| ohlcv / daily_ohlcv | `ticker`, `date`, `close`, `shares` |
| ohlcv / short_flows | `ticker`, `date`, `credit_bal_rate` |

실제 wu 표에는 `wu_rank`, `n_universe`도 있지만 계산에 사용하지 않는다. 신용 표에는 `credit_bal_qty`, `credit_bal_amt`, `fetched_at`도 있으나 커버리지는 사전등록의 `credit_bal_rate`만 사용한다. `daily_ohlcv_extra`는 읽지 않는다.

## 확인 못 함과 lv_e 도구와의 차이

- 실제 wu 점수·신용 값의 형식, 키 중복, 동결시각 파싱, 실제 점수 종목의 본표 존재 여부, 표본 수·성과·구간·실행 시간: **확인 못 함**. 구조만 확인했다. 키 중복은 향후 실제 실행에서 조용히 합치지 않고 오류로 보고한다.
- 10/06~08 신용 3개 열 전부NULL은 사용자 전달 배경이며 이번 작업에서는 재조회하지 않았다. 원인 및 동결 당시 자료 가용성: **확인 못 함**.
- 신용 지연 ‘지속’ 길이, 유니버스 지연 집계의 단일 정답, h10 재현·짝우위의 세부 문턱 및 완전한 해석표: **확인 못 함**. 두 집계를 병기하고 원시 조건을 출력한다.
- lv_e/lv_b → sv_b/sv_a, 등록9/01 → 9/14, lowvol_score → wu_score, 분모11 → **7 주 기준 +11 감도**, 방향은 **주 기준 계보**로 바뀐다.
- lv_e의 to20·시세 보충 감도·과매도30~40 각주는 제거하고 crb5 커버리지·지연·본표 종목 계수로 바꿨다. lv_e 적재50% 비교는 wu 판정 규약이 아니어서 가져오지 않았다.
- lv_e 짝비교 최소10과 달리 wu 선행 코드의 **최소3**을 사용한다. 화면 자동 라벨의 고정 숫자 문턱은 sv_b 판정으로 가져오지 않았다. 참고값 세 가지·수익·순위·재표집의 틀은 유지했다.

커밋·푸시, 배치·수집기·외부 호출은 하지 않았다. 산출물 외 테스트 파일·DB·중간 데이터 파일은 만들지 않았다.
