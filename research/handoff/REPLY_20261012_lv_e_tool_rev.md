# lv_e 도구 보완 — 시세 보충표 감도·각주 참고값

작업·검증: **2026-10-11 KST**. 파일명의 `20261012`는 요청대로 사용했다. 변경 산출물은 기존 `code_20261011_lv_e_verdict_tool.py`와 이 답변 두 파일이다.

## 결과

**실측:** 기존 가짜 자료 7개 사례와 추가 검증이 모두 통과했다. 보충표 전용 종목 포함, 본 표 종목 우선, to20 두 방식, 비겹침 수, 점수 지속성을 메모리 DB로 검증했다. 기존 주 계산도 가짜 자료 3종에서 변경 전과 일치했다.

**실제 DB에서는 `--schema`로 열 이름만 확인했다.** 실제 점수·가격·수익·점수 지속성은 계산하지 않았고 **`--real` 실행은 0회**다. 사용자에게 전달받은 ‘310행·55종목’, 키 중복·동결 시각 검토 결과를 이번 작업의 직접 실측으로 주장하지 않는다. 수집기·배치·외부 호출·운영 코드·docs·worklog 수정·커밋·푸시도 없다.

필수 최신 작업 기록과 지정 `VERDICT_NOTE_20261011_power.md`에는 과거 실측 지속성과 모의실험 수치가 있어 읽었다. 이들 수치를 새로 계산하거나 테스트 정답으로 사용하지 않았다. 금지된 리더보드 화면·텔레그램 기록·루트 `VERDICT_202610*_v30*.md`는 열지 않았다.

## 바뀐 곳

### 1. 주 계산과 보충표 감도 병기

- `read_inputs()`의 **본 표만 쓰는 주 계산을 유지**했다. 새 `with_extra_prices()`와 `read_price_variants()`가 별도의 감도 입력을 만든다. `extra_ohlcv` 및 다른 저장소 모듈은 import하지 않는다.
- 주 계산에 포함된 **본 표 종목 전체를 보충 대상에서 제외**한다. 해당 종목의 특정 날짜 종가·거래량이 비어 있어도 보충표로 채우지 않는다. 본 표에 아예 없는 종목만 보충한다. 이는 `extra_ohlcv.load_extra_close(..., exclude=본표종목)`의 종목 단위 우선 규약을 독립 구현한 것이다.
- 감도의 close와 to20 모두 같은 종목 우선 규칙을 쓴다. 보충 종목의 `volume/shares`를 본 표 날짜 격자에 놓고 rolling(20,min_periods=1)로 to20을 계산한다. 기존 본 표 to20은 그대로 둔다.
- **거래일 격자·등록일·자료 마감·게이트·동결점수는 두 방식에서 동일**하다. 기본 마감은 계속 본 표 마지막 날짜다. 보충표만의 날짜나 마감 이후 행이 평가 기간을 늘리지 않는다. 기존 `large_verdict.py`에서도 보충 종가를 본 표 날짜에 맞춰 붙이는 방식을 확인했다.
- 출력 맨 앞에 **본 표 / 보충 포함** n·평균·iid95 대조표와 to20 90% 미달 앵커 수를 나란히 낸다. 이후 각각의 전체 통계·주 블록·보정 구간·앵커별 커버리지·각주를 출력한다.
- 보류 검토는 어느 방식에서 발생했는지 첫 줄에 명시한다. 보충표 감도 결과가 주 계산의 보류 여부나 해석을 덮어쓰지 않는다.

### 2. 각주 ④ 참고값

`nonoverlapping()`, `score_persistence()`, `reference_values()`를 추가했다. 결과는 `reference`에 별도로 보관하고 출력한다. **기존 `legacy_label()`과 `interpretation()`은 수정하지 않았다.**

**① 겹치지 않는 앵커 수**

- 각 모델·h20/h10별로 `t+1+h < 가격 날짜 수`인 완결 앵커를 시간순으로 놓는다.
- 첫 앵커를 고른 뒤, 직전에 고른 앵커와 **거래일 위치 차이가 h 이상**인 앵커만 차례로 고른다. 관측 앵커 목록의 순번 차이나 달력 날짜 차이를 쓰지 않는다.
- 날짜상 완결 수와 비겹침 수·선택 날짜를 출력한다. 별도로 **실제 상관 산출에 들어간 앵커**에 한정한 같은 세기도 낸다. 후자는 시장 평균/통합, 각자/교집합, 단독/짝비교 표의 n과 대응한다.
- 이 수를 새로운 최소 표본 조건이나 라벨 조건으로 쓰지 않는다. 독립성의 증명으로도 해석하지 않는다.

**② 점수의 하루 지속성**

- lv_e와 lv_b 각각, 등록일 이후 해당 게이트·앵커 중복 제거를 통과한 **연속 두 유지 run**을 비교한다. h20/h10 미래 창 완결 여부로 제한하지 않는다.
- `(market,ticker)`가 공통인 종목에서 전 시장을 합쳐 두 점수를 각각 평균 동점 순위로 매긴 뒤 상관을 계산한다. 수익·가격 유효성으로 종목을 거르지 않는다.
- 상관 평균은 유효한 run 쌍의 동등가중 평균이다. 점수쌍 2개 미만이거나 한쪽이 상수면 상관은 ‘확인 못 함’으로 제외하고, 전체 run 쌍 수·유효 상관 쌍 수를 구분한다. 성과 IC의 최소 8종목 규칙을 이 참고값에 덧붙이지 않는다.
- **하루 뒤 같은 종목 비율 = 공통 종목 수 / 앞 run 종목 수**로 명시했다. 비율도 run 쌍별 동등가중 평균이다. 점수 결측으로 상관이 빠져도 종목 존재 비율은 따로 센다.
- ‘연속 run’ 사이에 빈 거래일이 있으면 그 쌍도 포함하되, 거래일 간격과 1일 초과 쌍 수를 출력한다. 이를 모두 정확히 하루 간격인 관측이라고 표시하지 않는다.
- 평균과 n, 참고용 날짜 iid95 구간 및 쌍별 세부값을 낸다. 참고 구간도 시계열 독립성을 보장하지 않으며 라벨에 쓰지 않는다.

## 실제 열 이름 확인

`--schema`에 `daily_ohlcv_extra`를 추가했고 검사가 성공했다. 두 시세표 모두 직접 확인한 열 이름은 다음과 같다.

```text
ticker, date, open, high, low, close, volume, change_pct,
shares, is_suspended, market, fetched_at
```

도구가 사용하는 필수 열은 `ticker,date,close,volume,shares`다. 구조 검사는 `PRAGMA table_info`뿐이며 실제 행 값은 읽지 않았다. 보충표가 없거나 필수 열이 없으면 ‘확인 못 함’으로 중단한다. 감도에서 사용하는 보충 시세의 날짜·종목 키 중복도 감지한다.

## 사용법·확인 못 한 것

사용 명령은 동일하다. 기본 실행도 가짜 자료 검증이며 결과 파일을 추가 생성하지 않는다.

```powershell
python -B research/handoff/code_20261011_lv_e_verdict_tool.py --self-test
python -B research/handoff/code_20261011_lv_e_verdict_tool.py --schema
```

판정 날 `--real` 한 번이면 주 계산과 보충표 감도, 각주 참고값까지 출력하도록 연결했다. **이번에는 실행하지 않았다.** 따라서 실제 성과 차이·실제 지속성·실제 실행 시간과 메모리 사용량은 **확인 못 함**이다.

to20 커버리지는 두 방식 모두 현재 원천표로 재구성한 값이다. 적재 당시 보충표를 사용했다는 뜻이 아니며, 동결되지 않은 당시 커버리지는 여전히 **확인 못 함**이다. 보충표 감도는 동결 점수·유니버스를 다시 만드는 작업도 아니다.

평일 금지 시간·skip_dates 예외·읽기 전용 DB·실제 계산의 명시적 `--real` 분리는 유지했다. 이 문서는 이전 답변의 ‘본 표만 출력’ 설명을 보완하며 이전 답변 파일은 수정하지 않았다.
