### 가장 단순한 발전 방향 — 나중

**제안:** 별도 `check_knowledge_drift.py`를 늘리기보다 같은 파일의 **정리 때만 쓰는 읽기 전용 함수**로 합친다. ‘마지막 정리 날짜’는 사람용으로 남기고, 실제 검토 범위는 **마지막 검토 HEAD+미커밋 기록 해시**로 남긴다. 다음 정리에서는 그 이후 바뀐 기록과 변경된 worklog 절을 후보로 모은다. 모든 내용을 의미 분석하거나 자동으로 승인 목록에 옮기지는 않는다.

worklog에는 예를 들어 `지식 반영: D35 · 출처: worklog/…#저녁-2`처럼 결정 ID와 절을 연결한다. ‘사용자 결정’이라는 정확한 제목만 찾지 말아야 한다. 현재 파일도 14행의 제목 외에 45행처럼 이어쓰기 절 내부에 승인 내용이 있다. 연결 없는 새 결정 후보는 **검토 경고**로만 보여 준다. 승인/제안/인용 구별과 내용 일치는 사람이 확인한다.

**기대 이득:** 커밋된 변경·기존 문서 정정·같은 날 추가 결정을 한 경로로 확인할 수 있다. **비용:** 최초 구현과 상태 형식 검증, 정리 담당자의 미연결 후보 대조. 매 Stop마다 전체 Git 이력이나 대화 기록을 읽는 비용은 만들지 않는다.

당장은 출력 이름을 **`정리 날짜 뒤 파일명 기준·명시 참조 없는 후보(누락 확정 아님)`**으로 고치고, ‘후보 0건’을 ‘반영 완료’로 쓰지 않는 편이 정확하다. **이득:** 부정확한 휴리스틱을 검증 결과로 오인하지 않음. **비용:** 설명 문구 변경만.

## 3. 정리 세션을 시작하는 가장 단순한 길

**판단:** 우선 SessionStart의 문맥 지시로 충분하다. 다만 현재 72행의 ‘사용자에게 정리를 제안’은 알림을 자동화할 뿐 실제 정리를 시작하지 않는다. 이미 승인된 정리 범위 안에서 다음처럼 지시를 구체화하는 안을 권한다.

> 정리 주기가 됐습니다. 이번 요청이 문서 수정을 허용하고 배치 제한 시간 밖이면, 현재 요청을 방해하지 않는 시점에 변경된 기록과 연결된 지식 행을 대조·압축하세요. 읽기 전용 요청·긴급 작업·배치 시간에는 미룹니다. 완료한 범위와 남긴 범위를 기록하고, 전체 대상 정리를 마쳤을 때만 마지막 정리 기준을 갱신합니다. 새 결정·판정·등록은 하지 않습니다.

**기대 이득:** 사용자가 매달 기억하거나 같은 정리를 재승인하지 않아도 된다. **비용:** 실제 대조 시간은 여전히 필요하며 해당 세션 담당자가 수행한다. 정리 권한이 없는 이번 검토 같은 요청에서는 실행하지 않는다. 이 지시가 모든 미완료 정리를 자동으로 끝낸다는 보장은 없다.

**별도 일정·새 스킬은 지금 불필요하다는 제안:** 세션이 없는 달에 정확한 시각에 정리할 요구는 없다. 예약 작업은 PC 상태·배치 시간·동시 편집·실패 후 재개까지 관리해야 한다. 별도 명령은 수동 재시도 편의가 필요할 때 현재 함수의 읽기 전용 진입점으로 추가하면 충분하다. **기대 이득:** 상태와 실행 경로를 늘리지 않는다. **비용:** 무접속 기간에는 다음 세션까지 정리가 늦어진다는 한계를 받아들인다.

공식 문서상 SessionStart는 새 시작뿐 아니라 resume·compact 등의 경우에도 실행될 수 있다. 따라서 정리 제안과 시작 상태 저장은 같은 세션에서 반복 초기화하지 않아야 한다. [Claude Code SessionStart 명세](https://code.claude.com/docs/en/hooks#sessionstart).

Stop의 호출 시점과 `stop_hook_active` 의미는 [공식 Stop 명세](https://code.claude.com/docs/en/hooks#stop)에서 확인했다. 로컬 hook의 실제 로딩·호출 성공은 이번에 확인하지 않았으며, 패치노트도 새 세션 확인을 남겨 두고 있다.

### 끄는 법

**실측:** 현재 스크립트에는 이 감시만 끄는 옵션이 없고 패치노트에도 중지 방법이 없다. 공식 문서는 설정 항목 제거 또는 `disableAllHooks`를 안내하지만, 후자는 다른 hook도 함께 끈다. [공식 비활성화 안내](https://code.claude.com/docs/en/hooks#disable-or-remove-hooks).

**제안:** 이 감시에만 적용되는 `KNOWLEDGE_GUARD_OFF=1` 확인을 main 맨 앞에 두고 패치노트에 사용자가 해당 환경으로 Claude Code를 시작하면 끄고, 값을 해제하고 다시 시작하면 복구된다고 적는다. 이는 **제안한 기능이며 현재는 작동하지 않는다.** 기존 방법으로 이 감시만 제거하려면 사용자가 `.claude/settings.json`의 해당 두 command 항목을 제거해야 한다. 설정을 실제로 변경하거나 hook을 비활성화하지 않았다.

**기대 이득:** 사용자에게 전체 hook을 끄거나 코드를 고치지 않는 중지 수단을 준다. **비용:** 환경 변수 분기 한 줄과 짧은 사용 설명. 꺼진 상태에서 지식 점검까지 자동으로 됐다고 보고하지 않는다.

## 5. 상한에 닿았을 때의 규칙 — 지금 분할하지 않음

> **24KB·15KB·5KB에 닿으면 먼저 중복을 압축하고, 그래도 넘을 때만 상세 근거·대체된 결정·해결된 함정을 주제별 보관소로 옮기되, 세 장에는 현재 적용 범위·닫힌 축·재검 조건·안전상 주의와 기존 ID/정본 링크를 남긴다.**

**기대 이득:** 매 세션 읽는 크기를 유지하면서 닫힌 실험과 옛 결정의 이유를 잃지 않는다. **비용:** 상한 도달 때 정리 담당자가 이동·링크 검사를 한 번 수행한다. 단지 오래됐다는 이유로 현재 유효한 결론을 숨기거나, 날짜별 보관소 전체를 다시 필수 읽기로 만들지는 않는다. hook의 참조 검사도 그때 새 경로를 따라가도록 보완한다.

### 나중: 효과가 큰 순서

1. **세션 시작 비교 기준**: HEAD·세 장/기록 해시를 session_id별로 보관하고, 같은 세션 재개 때 보존한다. 시작 기준이 없으면 ‘판단 불가’ 안내로 끝낸다. **이득:** 이전 dirty 상태와 커밋 뒤 누락을 구별. **비용:** 작은 상태 형식·동시 세션·재개 검증이 필요하므로 30줄 응급 수정에 억지로 넣지 않는다.
2. **정리 범위와 반영 ID 연결**: §2의 변경 기록 후보·D/K 연결을 정리 시점에만 확인한다. **이득:** 파일명 날짜와 단순 언급의 한계를 줄임. **비용:** 작성자의 반영 한 줄과 정리 담당자의 의미 대조.
3. **정리 진행 상태**: 한 번에 끝내지 못하면 완료 범위·남은 범위를 남기고 전부 끝난 뒤 정리 기준을 갱신한다. **이득:** 머리말 날짜만 바꿔 미처리 기록이 사라지지 않음. **비용:** 정리 담당자가 진행 범위 기록. 상시 스케줄러·별도 에이전트는 추가하지 않음.

권장 설명은 **‘지식이 저절로 쌓임을 보증하는 장치’가 아니라 ‘누락 후보를 알려 주고, 허용된 세션에서 정리를 시작하게 하는 장치’**다. 내용의 적절성은 정본 대조와 담당자의 기록으로 남는다.
