# REQUEST 002 — 리더보드 페이지, 사람이 알아보기 쉽게 (2026-09-13, Claude → Codex)

## 목적
`docs/leaderboard.html`(공개 주소 https://sj951027.github.io/dh-q7m3k/leaderboard.html)을 **비개발자 사용자가 5초 안에** 읽을 수 있게 표현·가독성·디자인을 검토해 달라.
읽는 사람은 이 스크리너의 주인 한 명이다. 실거래는 lv_b 를 따르고, v30 은 참고 챔피언이다. 텔레그램 링크로 **휴대폰에서** 연다.
페이지가 답해야 할 질문은 셋뿐이다:
1. 지금 내가 따라도 되는 모델은 무엇이고, 아직 보면 안 되는 모델은 무엇인가.
2. 따르는 모델이 최근에 어땠나(시장 대비, 얼마나 믿을 만한 숫자인가).
3. 다음 판정은 언제이고, 그때 무엇이 바뀔 수 있나.

## 읽을 것
- `docs/leaderboard.html` — 손으로 쓴 정적 페이지. 외부 라이브러리 0. JSON 7개를 fetch 해서 그린다(`leaderboard.json`, `leaderboard_history.json`, `models_registry.json`, `cross_sim.json`, `recent_ic.json`, `alpha_beta.json`).

- `docs/leaderboard.json` — 숫자의 원천(모델별 h5/h20 IC·n·CI·pos, verdict, oos_days, denom).
- 판정 규칙의 뜻: `CLAUDE.md` "불변 규칙" 절, `MODELS_LEDGER.md` 상단. 라벨 정의는 §11(`PROJECT_KNOWLEDGE.md` 에서 "§11" 검색).
- 최근 문구 정정 이력: `patch_note/20260913_gate_push_wording.md` ("그래서 뭐가 바뀌나" 절).

## 제약
- **파일 수정 금지**: `docs/`·`leaderboard.py`·`models_registry.json`·다른 저장소 파일을 고치지 않는다. 산출물은 `research/handoff/` 안에만.
- 판정 라벨(유의·기움·노이즈)의 **뜻을 바꾸는 제안은 하지 않는다**. 이름을 풀어 쓰는 것은 된다("기움" → 사람 말로 어떻게 쓸지). 단, 경계값은 '채택'이 아니라 '기움'이라는 보수적 태도를 흐리면 안 된다.
- "이 모델을 사라/따르라"는 표현은 registry 의 `money`·`live`·`reference` 범위를 넘지 않는다. 40거래일 미만 모델은 결과처럼 보이게 하지 않는다.
- 트랙이 다른 모델(v3 계열 vs 대형 가치 `large`)의 점수·IC 절대값을 나란히 비교하게 만드는 제안은 하지 않는다.
- 숫자는 항상 n·CI 와 함께 보여야 한다. 새 지표를 만들지 않는다(이미 JSON 에 있는 값만 쓴다). 새 숫자가 꼭 필요하면 "별도 승인 필요"라고 표시하고 계산식을 적는다.
- 외부 라이브러리·CDN 추가 없이 할 수 있는 제안을 우선한다. 
- `history.db`·`ohlcv.db` 는 열 필요 없다. 열더라도 `mode=ro`.
- 평일 20:10~22:30(KST)에는 실행·수정하지 않는다(오늘은 일요일이라 무관).

## 답 형식 (REPLY_002_leaderboard_readability.md)
1. **현재 페이지 실측**: 위 질문 3개를 지금 페이지가 어디서 어떻게 답하는지(표·열·문구 위치), 못 답하는 것은 무엇인지. 휴대폰 폭(약 390px)에서 어떻게 보일지는 CSS 를 읽고 추정으로 적어도 된다(실측/추정 구분).
2. **용어 바꿔 쓰기 표**: 현재 문구 → 제안 문구 → 이유. 최소 대상: "기움", "유의", "노이즈", "IC/순위 정확도", "확신", "h=20d", "20일 뒤 시장보다", "이긴 비율", "판정까지", "정본", "Bonferroni/분모", "OOS". 사람 말로 한 줄, 필요하면 툴팁용 두 줄.
3. **구조·디자인 제안**: 표의 순서, 첫 화면에 둘 것 1~3개, 색·배지·아이콘 규칙(색만으로 뜻을 전하지 않기), 휴대폰에서 표를 어떻게 접을지. 각 제안에 "왜 사람이 더 잘 알아보게 되는가" 한 줄. 우선순위(효과 큰 순) 매기기.
4. **오독 위험 지점**: 지금 문구 그대로면 사용자가 **잘못 행동**할 수 있는 곳(예: 판정 전 모델을 채택된 것으로 읽음, 기움을 채택으로 읽음, 트랙 다른 모델을 비교함). 각각 어디에 있고 어떻게 고칠지.
5. (선택) **정적 목업** `research/handoff/mock_002_leaderboard.html` — 현재 JSON 값을 파일 안에 상수로 박아 넣어 더블클릭만으로 열리게. 외부 자원 없음. 목업은 "이렇게 보인다"용이지 반영본이 아니다.
6. 실측/추정 구분. 다 못 본 것·모호한 것은 "질문" 절에.
