# 성적표 C안 이후 — 숫자보다 질문을 먼저 고르는 구조

2026-10-03 · Codex 검토. 사용자가 전달한 A/B/C 논의, 현재 로컬 성적표, 계산 코드, 운용 채택 사전등록을 대조했다. 화면·운영 코드 수정 없이 의견만 작성했다.

## 판단

**C안의 간결함은 유지하되, ‘차이’를 월 환산으로 바꾸는 것은 권하지 않는다.** 표가 어려운 이유는 설명 글자 수뿐 아니라 한 화면이 ‘얼마 벌었나·어느 모델이 낫나·믿어도 되나’를 동시에 답하려는 데 있다. 설명을 모두 숨기면 숫자를 해석하는 부담이 사용자에게 넘어간다.

추천은 **한 모델 성과 → 두 모델 비교 → 검증 기록**의 세 단계다. 처음부터 모든 모델·국면·시험 기록을 같은 표에 넣지 않는다. 전체 표가 필요하면 요약 화면으로 유지할 수 있다.

## 직접 확인한 사실과 수정할 설명

| 항목 | 확인 결과 | 의견 |
|---|---|---|
| 현재 첫 표 | 모델 수익·시장·차이·기간·개수·꾸준함, 결과 대기 모델까지 함께 있음 | C안에 정보가 다시 쌓였다. 핵심 세 숫자와 상세를 나눌 필요가 있다. |
| 폰 표시 규칙 | CSS가 모델 수익·시장 열을 숨기고 차이·기간·꾸준함을 남김 | 작은 화면에서 오히려 의미 설명이 필요한 숫자가 남는다. 모델 수익과 시장 대비 차이를 두 줄로 묶는 편을 권한다. |
| 꾸준함 | ‘40일 보유 시 시장을 이긴 목록 비율’과 ‘매일 매수 후 계속 보유한 계좌가 시장보다 앞선 날 비율’이 함께 표시됨 | 서로 다른 보유 방식의 두 비율이다. 첫 화면에서 빼고, 40일 상세에는 첫 비율만 정확한 이름으로 표시한다. |
| 월 환산 | `(40일 초과−0.35)÷2`는 사전등록의 크기 조건과 같은 식 | 실제 월 수익·월 예상 수익·매일 벌 수 있는 수익을 뜻하지 않는다. 상세의 ‘20거래일 단순 환산’ 정도가 적절하다. |
| 사전등록과 성적표 | 성적표 코드 머리에 희석 배지 제외·PIT 유니버스·40일 블록 CI 미적용이라고 명시됨 | 같은 환산식을 적용해도 정식 운용 시험이 되는 것은 아니다. 전 모델에 ‘채택 기준 통과’ 표시를 붙이지 않는다. |
| 정식 대상·기간 | v30·lv_b, 2026-09-17 이후 진입분. 현재 완결 성적은 마지막 목록 8/3 | 현재 돈 표는 정식 관찰기간의 결과가 아니다. +0.5 선만 가져와 정식 평가처럼 보여주지 않는다. |
| 모의계좌 cross_sim | 매일 상위20 교체·비용 0, 다음날 종가 진입 후 그다음 날부터 새 보유분 수익 | 일별 계좌 수익이지만, 40일 보유 성적표를 하루 단위로 펼친 결과는 아니다. |

현재 로컬 성적표는 브라우저에서 직접 열어 확인했다. 모바일에 관한 위 판단은 이번 턴에서는 반응형 CSS를 확인한 것으로, 375px 화면을 새로 실측한 결과라고 주장하지 않는다.

### 월 환산 표의 반올림 문제

`docs/scoreboard.json` 원자료로 직접 계산했다. 단위 %p.

| 모델 | 40일 시장 대비 차이 | 비용 0.35 차감 후 20일 단순 환산 |
|---|---:|---:|
| le_a | +10.733275 | +5.191637 |
| v30 | +3.814647 | +1.732324 |
| mom_a | +1.309478 | **+0.479739** |

mom_a는 소수 첫째 자리 표시로 +0.5가 되지만, +0.5 이상 조건에는 **미달**이다. ‘경계’는 별도 판정이 아니며 반올림한 표시값으로 기준 통과 여부를 정하면 안 된다. 위 계산은 표시 단위 확인이지 모델 우위에 관한 통계 검정이 아니다.

현재 화면에는 +20.5%−9.7%=+10.7%p처럼 표시 숫자끼리 빼면 0.1 다른 사례도 있다. 원자료에서 차이를 계산한 뒤 각각 반올림해서 생긴 것으로 계산 오류는 아니다. 세 숫자를 한 줄의 등식처럼 표현하지 말고, 상세에서 소수 둘째 자리까지 확인할 수 있게 하는 편이 좋다.

## 추천 D안 — 한 번에 한 질문

### 1. 기본: 한 모델의 40일 성과

첫 화면에서 모델 하나를 선택한다. 기본값은 마지막으로 본 모델로 유지하고, 전체 순위에서 수익 1등을 자동 선택하지 않는다. 다음은 **제안용 배치**이며 새로 구현한 화면은 아니다. 숫자는 현재 v30의 비용 전 참고 성적이다.

```text
성과 보기                      10/2 평가
[ 과매도 v30 ▾ ]

40거래일 보유 · 비용 전
        +7.1%
시장 +3.2%     시장보다 +3.8%p

38개 목록의 평균
[기간 확인]   [다른 모델과 비교]

기간이 다른 모델의 단순 순위가 아닙니다.
```

이 구조에서는 ‘−1.7%p’를 실제 손실로 읽을 가능성을 줄인다. 큰 숫자의 제목에 **40거래일 보유**를 붙여 오늘 수익·예상 수익과 구분한다. n은 독립 거래 횟수가 아니므로 ‘38번의 시험’ 같은 말은 쓰지 않는다.

‘기간 확인’을 누르면 날짜 흐름을 보여준다.

```text
평가한 목록: 6/5~8/3
마지막 목록 8/3 → 매수 8/4 → 40거래일 뒤 10/2 평가
각 목록을 따로 계산한 평균입니다. 보유기간은 서로 겹칩니다.
```

모든 행에 매수·매도 날짜 세 구간을 길게 반복하는 것보다 이 한 번의 설명이 낫다. 8/3은 수집 중단일이 아니라 마지막 완결 목록일이다. ‘40일’은 항상 ‘40거래일’로 표기한다.

### 2. 비교: 두 모델, 같은 조건

‘다른 모델과 비교’에서 두 모델을 고르고, **같은 목록 날짜·같은 시장이 성립한 표본**으로만 비교한다. 단순히 시작일·종료일 두 끝만 맞추는 것으로 충분하지 않다. 조건을 못 맞추면 한쪽 전체기간 수치를 대신 넣지 않는다.

- 첫 줄: 두 모델과 공통 평가 기간.
- 본문: 각 모델 수익, 공통 시장 수익, 두 모델 차이.
- 아래: 공통 목록 개수와 보유기간이 겹친다는 짧은 설명.
- 공통 완결 표본이 없으면 ‘같은 조건의 결과가 아직 없습니다’로 끝낸다.

여기서만 나란히 막대나 연결점 그림을 쓰면 무엇을 비교하는지 분명해진다. 기존 전체기간 결과를 공통기간 비교처럼 그리지는 않는다. 차이가 양수라고 승자 배지·추천 표시를 붙이지 않는다.

### 3. 검증 기록: 시험 결과·자료·방법

순위 검증, 정식 운용 시험, 국면별 기록, 묶음, 모의계좌는 여기서 접근한다. 각각 무엇을 잰 것인지 제목으로 구분한다. 특히 대형 트랙은 후보군과 잣대가 달라 비교 선택기부터 분리한다.

새 결과 대기 모델은 성과 표의 숫자 없는 행으로 반복하지 않고 ‘결과 대기 3개’ 같은 접힘으로 모은다. 다음 일정은 가장 가까운 하나와 ‘전체 일정’만 보여준다. 첫 40일 성적이 나오는 날과 정식 판정일은 같은 종류의 일정으로 표시하지 않는다.

## 전체 모델 표를 유지한다면 — 작은 변경안

모든 모델을 한눈에 보는 것이 더 중요하면 다음 **3열 표**만으로도 개선 가능하다.

| 모델 | 40거래일 성과 | 기록 |
|---|---|---|
| 과매도 v30 | **+7.1%** / 시장보다 +3.8%p | 38개 목록 · 상세 |
| 저점탈출 le_a | **+20.5%** / 시장보다 +10.7%p | 13개 목록 · 상세 |

제안용 일부 행이며 비용 전 숫자다. 수익과 차이를 같은 셀의 두 줄로 두면 폰에서도 한쪽을 없앨 필요가 없다. 기본 순서는 고정하고, 수익순은 사용자가 선택할 수 있게 한다. 공통기간을 실제로 적용하지 않은 상태에서는 표 위에 **‘모델별 평가 기간이 다릅니다’** 한 줄을 남긴다.

첫 화면에서 뺄 것: 월 환산, 두 종류의 꾸준함, 긴 다음 일정, 국면별 성적, 순위 시험 열, 추정상 좁은 참고 CI. 이 정보가 무가치해서가 아니라 같은 질문에 답하지 않기 때문이다. 원자료·검증 방법은 상세에서 찾을 수 있어야 한다.

행 전체가 눌리는 것을 추측하게 하지 말고 명시적인 ‘상세’ 버튼을 둔다. 이름은 종목 목록으로 이동하고 행의 다른 곳은 펼쳐지는 현재 방식은 동작이 달라 헷갈릴 수 있다. 버튼은 키보드·터치로 모두 조작할 수 있어야 하고, 양수·음수 의미는 색만으로 구분하지 않는다.

## ‘하루 평균’을 정말 보고 싶다면

두 가지를 구분해야 한다.

1. **40일 성적의 단위 환산:** 차이÷40은 40일 평균 초과를 선형으로 나눈 값이다. 매일 그만큼 벌었다는 뜻이 아니다. 복리 일환산도 수익 경로를 복원하지 못한다. ‘하루 평균 수익’이라는 대표 제목은 피한다.
2. **보유 계좌의 실제 일별 변화:** 종목·비중·현금·진입·청산·비용을 정한 모의계좌에서 당일 손익을 계산해야 한다. 매일 사서 40일 보유한다면 초기 현금, 매일 투입 금액, 새 납입금과 운용 수익의 분리까지 필요하다. 평균 하루 수익 하나보다 누적 수익·시장 대비·최대낙폭을 같이 보는 편이 질문에 더 잘 답한다.

현재 cross_sim을 두 번째 화면으로 사용할 수는 있지만 **‘매일 교체 모의계좌·비용 전’**이라고 분명히 표시해야 한다. 40일 보유 전략의 일별 운용 성과가 필요한 경우에는 별도의 연구 질문이다. 현재 성적표의 평균을 나눠 대신 채우지 않는다.

## 화면 검증에 쓸 네 질문

새 디자인이 더 좋은지는 글자 수보다 다음 질문에 답할 수 있는지로 확인하는 편이 낫다.

- 화면의 큰 숫자는 모델 수익인가, 시장 대비 차이인가?
- 8/3에 자료가 멈춘 것인가, 40일 결과가 끝난 마지막 목록인가?
- le_a와 v30는 같은 기간을 비교하고 있는가?
- +0.5로 표시되면 정식 운용 채택이 된 것인가?

설명서를 열기 전에도 오해 없이 답할 수 있어야 한다. 특히 두 번째·네 번째 질문은 실제 대화에서 혼동이 드러난 지점이다.
