## 1. 독립 설계(DESIGN 열람 전 기록)

[실측] 질문 1·2를 먼저 이 파일에 쓴 뒤 DESIGN을 열었다. 같은 대화의 앞선 구조 검토와 이번 요청서의 설계 개요는 알고 있지만, DESIGN 본문은 사전 열람하지 않았다. 세 장은 각각 23,774·14,980·4,923바이트이고 K 행은 41개다(직접 집계).

[제안] **① 매번 읽기**: 공통 안전 규칙·정본 우선순위·짧은 분야 안내·최신 작업 인계·현재 요청에 걸리는 미완료 약속만 기본으로 읽는다. 상세 결론·과거 결정·연구별 함정은 해당 작업 때 읽되, 적용 중인 결정·자료 한계·반증 자료를 함께 불러온다. 바꿀 대상은 저장 용량보다 매번 읽는 양이다. 기존 정본·기록은 삭제하지 않는다. 이득은 결론 증가와 시작 비용의 분리, 비용은 작성자가 새 결론의 적용 범위와 분야를 붙이는 일이다(현 읽기 규칙 변경은 별도 승인 후).

[제안] **② 찾기**: ‘무슨 질문/작업인가 → 분야 → K/D/P와 정본’의 표를 둔다. 모델명·일상 표현·자료명 별칭과 함께 필수 동반 자료를 연결한다(예: 수익 연구→K39·K40, lv_e 교체→K18·D31·관측 계약). 처음엔 이 표와 `rg`만 사용한다. 검색 0건은 결론 없음이 아니라 미확인으로 취급하고, 옛 기록·정정 관계까지 넓혀 찾는다. 과거 질문과 필요한 근거 목록을 묶어 새 경로가 같은 제한·예외를 찾는지 확인한다. 이득은 누락 발견, 비용은 연구자가 누락 사례가 생길 때 별칭·연결과 확인 사례를 보강하는 일이다.

[제안] **③ 100·300개**: 모든 K 한 줄을 계속 기본 문맥에 넣으면 결국 다시 찬다. 분야별 목록으로 나누고 전체 ID 목록은 필요할 때 검색한다. 본문 위치는 ID마다 하나, 교차 분야는 링크로 연결한다. 결정의 효력·구현 여부·약속 완료는 각각 D/K/P의 담당 원본에 둔다. 분야가 커져도 상세 결론이 기본 문맥에 누적되지 않는 구조다. 이득은 증분 확장, 비용은 정리 담당자가 링크·대체 관계·찾기 실패를 점검하는 일이다. 300개에서의 실제 읽기량·누락률은 아직 측정하지 않았다.

## 2. 새 관점을 만드는 습관(DESIGN 열람 전 기록)

## 5. 추가 부작용과 혼합 기간

1. **기존 장치와 자료 형식의 불일치.** [실측] `tests/knowledge_guard.py:150–151`·`tests/test_knowledge_sheets.py:81`은 두 자리 ID만 읽고, guard:285는 세 장 해시만 본다. [제안] K100·D100 이상, 새 카드의 변경·중복·정본 연결도 검사가 읽도록 카드 도입과 함께 맞춘다(누락·반복 번호 방지 / 구현자의 호환 검사).
2. **한 카드가 여러 결론을 억지로 하나로 만듦.** [실측] K26은 여섯 축, K34는 비용·결제·한도·자본을 묶는다(`KNOWLEDGE.md:35,44`). [제안] 서로 다른 상태·재검 조건이면 본문에 항목별로 남기고 자동으로 한 상태를 붙이지 않는다. 향후 분할 때 옛 K를 연결용으로 보존한다(부분 결과의 오독 방지 / 편집자의 항목 대조).
3. **원리 탐색 자체가 같은 자료에 맞춰짐.** [제안] 여러 설명 중 결과에 맞는 것만 남기면 기대 적중률도 과장된다. 후보·기각 이유·공유 표본을 함께 남기고, 새 가설의 기대·실패 조건은 새 결과 전에 고정한다(과적합 억제 / 연구자의 탐색 이력 기록). 원리 변경으로 판정 조건을 바꾸지는 않는다.

[제안] **혼합 기간**에는 ID→현재 위치를 하나로 정한다(옛 행 또는 카드). 원문 보존 뒤 옛 자리는 이동 안내로 바꾸고 두 곳에서 현재 결론을 편집하지 않는다. 두 형식을 함께 읽되 중복 ID는 오류로 드러낸다. 숫자뿐 아니라 부정어·범위·예외·출처·승인 상태도 대조한다(의미 보존 / 구현자의 호환 읽기＋편집자의 검수).

[실측] P04·P05·P07의 예정일은 각각 ≈12/18·12/28·12/30이고 P06은 ls_t1 정의 미결을 담는다(`PROMISES.md:18–21`). [제안] 세 판정의 정본·계약·해당 K/D/P 위치는 판정 전후 대조가 끝날 때까지 유지한다. 이전 시험은 새 결론 또는 판정과 무관한 소수 항목으로 한다(판정 준비 보호 / 담당자의 대상 제한). 실패하면 그 묶음만 원위치로 돌리고 이후 생긴 지식은 보존한다.

## 6. 순서와 하지 말 것

[제안] 순서는 **수동 안내·찾기 기준 → 새 결론 소수 카드＋호환 검사 → 필요 시 스크립트 → 판정 뒤 기존 자료 이전**이다. 원리 첫 판은 비교 메모로 병행하되 기존 행의 축약 근거로 삼지 않는다. 경로 규칙은 공통 읽기 절차의 보조로 시험한다(누락 조기 발견 / 연구자·구현자의 작은 시험).

[제안] **지금 금물**: 원리 개수 강제·기존 결론 대체·대량 이동·자동 주입·상시 사서·상한 증액만 하기. **12월 판정 뒤**: 관련 K/D·절차 위치 변경과 전체 카드화. ‘한 달 지남’ 대신 기존 질문의 필수 근거·예외 누락 0, 깨진/중복 ID 0, 수치·의미 차이 0을 시험 묶음에서 확인한 뒤 확대한다(무리한 전환 방지 / 담당자의 비교 기록). 미래 누락까지 보증하지는 않는다.

[실측] 지정 REPLY 외에는 변경하지 않았다. DB·배치·hook·저장소 스크립트를 실행하지 않았으며, 100/300개 실운용·카드 검색 정확도·앱 자동 주입은 미검증이다.
