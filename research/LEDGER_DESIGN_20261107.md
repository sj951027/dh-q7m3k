> **지위**: `AUTOMATION_ROADMAP_20261107.md` §3 1단계 "만들 것"의 설계 정본. 장부(`AUTOMATION_BACKLOG.md` §1)의 🧪 8건이 여기서 정의한 통과 조건으로 시험된다. 결정 종류는 🔒 고정 / 🔁 자유(장부 규칙 ⑥).

## 0. 한 줄 결론
- 돈 장부는 **모의 계좌 엔진의 소비자**다. `paper_engine.py`·`paper_account.py`·점수·판정 코드는 바꾸지 않는다(0-diff). 돈 장부가 멈춰도 배치·표시는 그대로 돈다.
- 되감기(8/10~)로 **L0(분수주·T+0) 장부 × 300만원 = 비율 탭 × 300만원** 을 먼저 보이고(허용오차 1원/일), 그 뒤 (a)→(b)→(c) 사다리를 변수 하나씩 올린다.
- 실제 증권사와 맞는지는 **2단계(사람 체결)·2.5단계(모의투자)** 에서 대조한다. 1단계는 증권사 없이 끝낼 수 있다 — "실제로 잘 돌지"는 그때 본다(사용자 11/7 질문의 답).

## 4. 돈 규칙 (1단계 🔁 — 단, 비교군과 같은 값은 바꾸지 않는다)
1. **예산**: 그날 신규 예산 = NAV(전일 마감) / 40. L0 는 목록 n 종목 균등(= 엔진), S_ 는 1종목 전액.
2. **매수가**: 추천 다음 거래일 **종가**(ENTRY_LAG=1, 모델 가정). 종가는 이미 호가 단위 위라 반올림 없음. (2단계 계획서의 '예상가'에만 호가 단위 표 A1 적용.)
3. **수량**(S_b~): `qty = floor(예산 / 매수가)`. qty = 0 이면 SKIP(사유 `budget_lt_1_share`) → 현금. 잔돈 = 예산 − qty×매수가 → 현금(재투입 없음, B4).
4. **비용**: 기본 계좌는 **왕복 0.5%** (매수 0.25%·매도 0.25%, 비율 탭과 같게). 실측 요율은 **뱅키스**(사용자 11/7 확인: 왕복 ≈0.235%, §13 표) — `cost_profile=bankis` 를 병기 열로 둔다(🔁 v2, 기본 계좌 규칙은 0.5% 그대로). 원 단위 절사 방식(수수료 원 미만 절사 여부)은 체결 내역으로 2단계에 확인.
5. **청산**: 진입 40거래일 뒤 종가 전량. 비용 차감 뒤 매도대금 → L0·S_a·S_b 는 즉시 현금, S_c 는 `pending_settle` 큐(2거래일 뒤 현금).
6. **S_c 의 돈 제약**: 그날 예산 > 쓸 수 있는 현금이면 **현금만큼만**(qty 재계산), 부족분은 SKIP(사유 `cash_short`). 미수 없음.
7. **평가**: 매일 종가(없으면 마지막 유효 종가). NAV = 현금 + Σ(qty × mark) + pending_settle.
8. **재투입 없음**: 잔돈·SKIP 현금은 다음 날 NAV 에 들어가 NAV/40 로만 돌아온다(엔진과 같음).

## 5. 이벤트 원장 (append-only) — E3
| 열 | 뜻 |
|---|---|
| `event_id` | `sha256(account_id|trade_date|type|ticker|seq|payload)` 앞 16자 — **같은 이벤트 두 번 넣으면 두 번째는 무시**(PRIMARY KEY) |
| `account_id`, `trade_date`, `seq` | 계좌·거래일·그날 안 순서 |
| `type` | `OPEN`(시작 자본) · `PLAN`(예산·목록 스냅샷) · `FILL_BUY` · `FILL_SELL` · `SKIP`(사유) · `SETTLE`(T+2 현금화) · `MARK`(일말 평가 요약) · `CORP_ACTION`(분할·병합·권리락 수량 조정) · `EXTERNAL_CASH`(입출금, 2단계~) · `REVISION`(평가가 바뀐 종가 기록) · `DELIST`(시세 끊김 처리) |
| `ticker`, `qty`, `price`, `amount`, `fee`, `tax` | 정수 원·정수 주(L0·S_a 는 분수 허용 — §8) |
| `ref_run_id`, `src_hash` | 입력 run_id · 입력 목록 해시 |
| `payload_json` | 사유·지연 일수·마지막 유효가 날짜 등 |
- **재생(replay)**: 상태 = 이벤트를 날짜·seq 순으로 접은 결과. 상태 테이블(`ledger_nav`·`ledger_positions`)은 **파생물**이라 지워도 재생으로 복구된다(백업 시험 G5 의 근거).
- **중간 종료**: 어느 날짜까지 쓰다 멈춰도, 다음 실행은 "마지막 MARK 다음 거래일"부터 이어 쓴다. 통과 조건: 한 번에 돌린 것과 **NAV·수량 완전 일치**.
- **되감기 재실행**: 같은 run_id 입력이면 이벤트가 전부 중복 → 0건 추가. 입력이 달라지면(시세 정정) REVISION 만 추가되고 과거 FILL 은 바뀌지 않는다.

## 6. 항등식·상태 (E1 — 매일 검사, 어긋나면 그날 장부 `state` 로 표시하고 다음 날 계산 중단)
- `cash + Σ(qty × mark) + pending_settle == nav` (정수 원, 오차 0)
- `pending_settle == Σ(미도래 SETTLE 금액)`
- 보유 수량 ≥ 0 · 현금 ≥ 0(미수 금지) · 같은 (ticker, entry_date) 포지션 1개
- 상태기계(포지션): `planned → filled → (held …) → exit_due → sold → settled` / 갈림: `skipped`(사유) · `delayed_exit`(정지) · `delisted`.

## 7. 사건 처리 (엔진 규칙과 같게 — 다르면 엔진이 정본)
1. **정지 중 만기**(A6·C10): 만기일에 거래 불가면 마지막 유효가로 평가 유지, **재개 첫 종가**에 청산, `delay_days` 기록. 장부 열 `n_delayed`.
2. **상폐·시세 끊김**(A7): `gone` 날부터 마지막 유효가 × 0.1 로 평가(엔진 −90% 감도와 동일), DELIST 이벤트, 잔액은 현금 0 으로 확정(실계좌 단계에선 사람 처리 목록).
3. **권리락·분할·병합**(A8): 되감기 입력이 **수정주가**면 수량 사건이 가격에 녹아 있어 CORP_ACTION 없음(L0·S_a 와 같은 결과). 실계좌·모의투자 단계는 잔고 조회로 수량 동기화 → CORP_ACTION(비율·사유). **DB 종가가 수정주가인지**는 구현 전 확인 항목(§13-1 확인 항목 그대로) — 아니면 사건 표(분할 비율)를 따로 받아야 함.
4. **결손일**(D1·F2): 본표에 그 날짜가 없으면 MARK 없음(마지막 유효가 유지), 그날 추천은 다음 본표 거래일 기준으로 ENTRY_LAG 적용(엔진과 동일).
5. **시세 정정**(D3): 실측(§13) — 20:10 수집 종가는 매일 **2~3%(49~74종목)** 가 다음 날 바뀌고 86% 가 ±0.5% 미만, 최대 ±3%. 장부는 평가에 쓴 가격을 MARK 에 스냅샷하고, 바뀌면 REVISION 이벤트(old·new·차액). **과거 NAV 는 고치지 않고** `revision_impact` 열(정정 반영 시 NAV 차)만 병기 — 비율 탭(재수집값 사용)과의 1원 차이는 이 열로 설명돼야 통과.
6. **상한가·거래정지 날 진입**: `tradable=False` → SKIP(`not_tradable`) → 현금. 대체 종목 없음(J05 닫음).

## 8. 정밀도 (E4)
- 내부: **정수 원(int)·정수 주(int)**. L0·S_a 분수주는 `Fraction` 또는 1e-9 단위 정수(원×1e9)로 들고 표시만 반올림.
- 비용: `floor(amount × rate)`(원 미만 절사 가정 — 2단계 체결 내역으로 확인 뒤 🔁 수정).
- 통과 조건: 3,000만→300만 환산(L0) 최대 오차 ≤ 1원/일 · S_ 계좌는 정수라 오차 0.

### 9-2. 사용자 화면 결정 (2026-11-07, Codex 사용성 검토 5-1·5-2 반영 — 표시 전용, 계산 무변경)
- **기본은 S_c 한 장.** 화면 이름 `모의 300만원 · v30 · 1주 단위 · 결제 2거래일`. S_a(분수주)·S_b(정수주)는 `소수점 매수·결제일 차이 보기`로 접고, L0 는 검증 자료로만 둔다.
- **첫 줄** = `다음 거래일 ○○ · 예산 ○만원(추정) · 쓸 수 있는 현금 ○만원`. 수량은 `기준가 ○원으로 약 N주`로만 쓴다 — 다음 거래일 종가는 아직 없으므로 **확정 체결 수량이 아니다**.
- **둘째 줄** = `총자산 / 쓸 수 있는 현금 / 결제 대기 대금(예정일)`.
- **미진입** = `신규 진입 대상 N거래일 중 M일` 한 줄 + 원인 펼침(예산 부족 · 보유 중 · 후보 없음 · 미체결).
- **합성 표(§14 S1~S10)** 에는 `가상 시험 · 짧은 보유기간` 을 고정 표시해 실제 운용 성적과 섞어 읽지 않게 한다.

## 17. 2단계 연결 초안 — 계획서·대조 열 (지금은 모양만, 숫자 규칙은 2단계 사전등록 때 동결)

- 멱등: `(account_id, ptw_trade_id)` 가 같으면 재수입해도 한 번만 반영, `(odno, fill_seq, event_type)` 이 같으면 같은 사건으로 본다. 중복은 무시하고 로그 한 줄.
- 부분체결: 같은 `odno` 의 `FILL` 행 여러 개, `Σqty ≤ ord_qty`. 최종 체결 = `Σqty == ord_qty`(또는 `cum_filled_qty == ord_qty`). 넘치면 그 주문 전체를 `대조 미완료`.
- 취소·정정: `CANCEL` 은 `orgn_odno` 로 원주문에 붙고 그 수량만큼 `unfilled` 칸. `AMEND` 는 KIS 가 **새 주문번호**를 주고 `orgn_odno` 로 원주문을 가리키는 구조(공식 문서 `orgn_odno`·정정취소 API `ORGN_ODNO`) — 원주문 사슬을 따라 한 계획 줄로 묶는다. 사슬이 끊기면 `대조 미완료`.
- 수동 식별: `plan_id` 빈칸 **또는** `event_type=MANUAL_FILL` **또는** `model` 이 계좌의 모델과 다르면 → 대조표 `manual` 칸(§17). 계획에 있는 종목이라도 수량이 계획과 다르면 차이분은 `unfilled`/`manual` 로 나눈다.
- 자료 기준일: `as_of_date` 가 대조 대상 날보다 앞서면 **그 날 대조는 보류**(파일이 아직 안 나온 것으로 본다). 같은 날 파일을 두 번 받으면 늦은 `exported_at` 이 이김(멱등 키로 사건은 중복 안 됨).
- 형식: `format_version` 이 모르는 값이면 읽지 않고 알림. 수량·단가가 정수가 아니면 행 거부(PTW float → 정수 변환은 PTW 쪽 또는 사람이).

**4) 단계별 채움 — PTW 를 안 고치고 시작하는 임시 규약(2단계).**
- 지금 파일 `ptw_trades.csv` 를 그대로 읽어 v0 의 필수 열을 만든다: `ptw_trade_id←id`, `code`, `side`, `qty`, `price`, `fill_date←traded_at`, `source=manual_ui`, `event_type=FILL`, `fill_seq=1`, `format_version=ptw_trades/legacy`, `as_of_date` = 파일 받은 날(사용자가 장 마감 뒤 내려받는다는 약속), `account_id` = 사용자가 정한 고정값(이 계좌는 자동화 전용 — 장부 §2 ❓).
- `plan_id`·`odno` 는 **매도 메모(`sell_note`) 또는 종목명 뒤 꼬리표**로 임시 전달하는 방법이 있으나, 매수 행에는 메모 칸이 없어 **매수 체결의 계획 연결은 `(fill_date, code, side, model)` 로 계획서와 맞춘다**(같은 날 같은 종목을 두 번 사면 구분 불가 → 그 경우 `대조 미완료`). 이 한계가 2단계 첫 2주 실측(장부 §2 '계획 vs 사람 체결 대조')의 측정 대상이다.
