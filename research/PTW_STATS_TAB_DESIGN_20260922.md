## 1. 집계 정의

### 1-1. 매도별 실현손익 = '반올림된 누적값의 차분'
- 사용자의 **전체 거래 이력**(선택 기간 이전 매수 포함)을 `positions_from_trades()` 와 **같은 순서**(종목별 거래일 정렬, 같은 날은 입력 순서)로 앞에서부터 한 건씩 늘려 가며 반복 호출한다.
- 누적 실현손익 C(k) = 완료된 보유주기 손익 합 + 현재 보유 중 주기의 부분매도 실현손익 합(둘 다 기존 함수 반환값). 매도 k 의 손익 = C(k) − C(k−1). 결과를 기간(월/주)으로 필터링한다.
- **반올림 정의(화면·문서 공통 문구)**: "매도별 손익은 원 단위로 반올림된 누적 실현손익의 차이로 계산합니다. 개별 매도의 반올림 전 손익과 원 단위 차이가 생길 수 있습니다." (재현: 평단 100.5원 사례에서 8/20 매도 +0.5 → 0원, 9/3 매도 → +1원. 합계는 일치.)
- 장부 규칙을 복제하지 않는다(기존 함수 재사용). 비용은 거래 수 제곱으로 커지므로 **실제 건수로 측정** 뒤 필요하면 개선하고, 그때 이 방식을 비교 기준으로 쓴다.
- **합계 검증 기준**: 전체 기간 합 = **청산 완료 보유주기 손익 + 보유 중 주기의 부분매도 실현손익**(청산 탭만 비교하면 부분매도분만큼 다르다).

### 1-2. 건수·승률(전체만)
- 청산 1건 = 전량 매도로 끝난 보유주기 1개, 기간 키 = `closed_at`. 수익·손실·**본전(0원)** 세 건수를 그대로 보이고, '수익 거래 비율' = 수익 건수 ÷ 청산 완료 건수(분모 표기).
- 실현손익(매도일 기준)과 건수(청산 완료일 기준)는 집계 단위가 다르다 — 화면 본문에 한 줄로 적는다(툴팁 금지).

### 1-3. 출처별 = '출처별 배분 손익' + 관련 보유주기 수
- 보유주기 안에서 **출처별 잔여수량**을 따로 추적한다: 매수는 그 출처 잔여수량에 더하고, 매도 직전 잔여수량 비율로 손익을 배분한 뒤 같은 비율로 잔여수량을 줄인다. 전량 청산 뒤 재매수는 구성 초기화.
  (예: lv_b 10주 매수 → 8주 매도 → v30 8주 매수 → 잔여 lv_b 2 : v30 8 = 20:80. 기존 `model_mix` 는 매수 합산 10:8 이라 통계에는 쓰지 않는다. 카드 표시용 `model_mix` 는 그대로.)
- 출처 판별은 `model_label.resolve_model`(명시 라벨 → 태그 유추 → 직접 고름) 재사용. 유추 출처와 명시 출처는 상세에서 구분 표시.
- 이름은 **'출처별 배분 손익'**. "실제로 그 출처에서 얼마 벌었는지" 가 아니라 배분 규칙임을 본문에 명시. 출처별 승률은 1차 제외.
- **배분은 부호를 보존**한다: 절댓값을 비례 배분해 내림한 뒤 남은 원을 소수부 큰 순서로 나누고 마지막에 부호 적용(+2원을 3:3:3:1 로 나눠 −1원이 생기던 '항목별 반올림+잔차' 방식 폐기 — Codex 3차 검토).
- **'관련 주기 수' = 그 기간에 매도가 있었던 보유주기 수(출처별 중복 제거)** — 같은 주기를 여러 번 부분매도해도 1건, 부분매도만 있어도 1건(청산 시점만 세던 초기 구현은 '배분 +100 / 0건' 이 나왔음). 서로 겹칠 수 있음을 표기.
- **명시/추정 구분**: 거래에 붙은 라벨은 명시, 전략 태그 유추는 추정. 배분에 추정분이 섞이면 출처 이름 뒤 '(추정 포함)'.
- **출처 조회 실패**는 빈 결과로 숨기지 않는다: `labels_status: error` 면 전체·전략별은 유지하고 출처별(`by_source`·매도 상세 `alloc`)만 null → 화면 '출처 라벨을 읽지 못했어요'.
- **매도 상세 내역**: 행마다 `sells[]`(매도일 기준·최근 먼저·부분매도 표시·매도 시점 전략·출처 배분). 화면은 3건 + 모두 보기.

### 1-4. 월말(주말) 평가손익
- `DailySnapshot` 의 각 기간 **마지막 행**(`total_pnl`·`realized_total`·`date`). 실현손익과 합산하지 않는다. 표기: "8/31 보유분 평가손익 −120,000원" 처럼 **실제 기록 날짜**와 함께. 기록이 없으면 "기록 없음".
- 상세에 '거래원장 재계산값(실현손익)' 과 '당시 저장값(평가손익)' 을 구분 — 과거 거래를 수정하면 앞은 바뀌고 뒤는 그대로일 수 있다.

### 1-5. 명시 사항
- 수수료·세금 제외(원장에 비용 없음 — '순수익' 이라 부르지 않음). 현재 월은 '진행 중 · N일까지'. % 지표(매도대금 대비·원가 대비)는 1차 제외.
- 상태는 **영역별로** 서버가 내려준다: `trades_status`·`snapshot_status`·`labels_status` 각각 `ok | empty | error`(조회 실패 / 기록 없음 / 실제 0원은 ok 에 값 0). 거래 통계는 성공하고 스냅샷만 실패할 수 있으므로 하나로 합치지 않고, 정상 손익을 오류 화면으로 가리지 않는다. try/except 로 조용히 0 으로 바꾸지 않는다.
- **전략별 귀속**(화면의 '전략별' 전환): 매도 1건의 손익은 **그 매도 시점에 그 보유주기에 적용되던 전략**(장부 함수가 그 시점까지의 매수에서 정한 값 = 마지막 매수의 전략)에 넣는다. 현재 전략으로 과거 매도분을 다시 분류하지 않는다. 알려진 한계: 전략은 매수 거래 행에만 저장되므로 사용자가 과거 매수의 전략 태그를 수정(PATCH)하면 그 시점의 재계산값도 따라 바뀐다(전략 변경 이력 테이블은 1차 범위 밖).

## 2. API — `GET /api/stats?period=month|week&limit=12`
- 로그인 보호, 읽기 전용, DB 쓰기 0. 본체 `compute.stats_payload(user, period, limit)`. 입력 검증(period 화이트리스트, limit 1~60), 사용자별 격리는 `current_user` 기준 — 테스트 항목.
- 응답: `rows[]` = {key, label, realized(매도일 기준·부분매도 포함), n_sells, n_partial, n_closed, n_win, n_loss, n_even, by_source{model:{allocated, n_cycles, inferred}} | null, by_strategy{tag:{realized, n_sells}}, sells[], snapshot_end{date,total_pnl,realized_total} | null, in_progress}, `total_check` = {closed_sum, open_partial_sum, all_sells_sum, match}, `trades_status`, `snapshot_status`, `labels_status`, `models`, `basis`.
- 주 키 ISO 주(월~일). 집계도 월~일(표시를 월~금으로 자르지 않음).

## 3. 화면 — Dashboard 세 번째 탭 '통계'(시안: Codex `ptw-stats-preview.html`, 구조만 참고)
- 읽는 순서: 기간 선택 → **실현손익 하나**(큰 숫자) → 청산 완료·수익/손실/본전 건수 → 월별 실현손익 막대(6개월, 진행 중 표시) → 출처별/전략별 전환(배분 손익·관련 주기 수) → 매도 내역(발생일 기준, 부분매도 표시).
- '월별 기록' 보기: 행 = 월, 펼치면 두 번째 줄에 월말 평가손익(날짜 포함). 모바일은 열 추가 대신 두 줄.
- 총자산·현금·평가액 카드 반복 금지(보유 화면과 중복). 출처마다 색·순위·왕관 없음. 집계 기준 문장은 본문 하단 상시 노출.
- 구현 시 시안의 `light-dark()`·`window.openai`·`Tweak` 는 쓰지 않고 PTW 기존 Tailwind 클래스로 옮긴다. 자동 문장은 계산 사실만("8건 중 5건 수익"), 평가·권고 문구 없음.

## 4. 테스트 — `test_stats_payload.py`(순수 로직, sqlalchemy 없이 dict 입력)
1. 합계: 전체 기간 매도별 손익 합 == 청산 완료 손익 + 보유 중 부분매도 실현 2. 반올림 재현(평단 100.5원, 월 경계 잔차) — 문구대로 동작 3. 월 경계 부분매도 귀속(8월 +100, 9월 0) 4. 출처 잔여수량 배분(10→8매도→v30 8매수 = 20:80) · 전량 청산 후 초기화 5. 동일 종목 재진입 분리 6. 0원 = 본전 7. 스냅샷 누락 → `snapshot_end null`·`snapshot_status empty`, 거래 정상 + 스냅샷 조회 실패 → `trades_status ok`·`snapshot_status error`(rows 는 유지), 실제 0원 → `ok` 8. 월/주 총합 비교는 **같은 시작·종료 기간**에서 9. 원 단위 표시 합계와 출처별 반올림 합계 대조 10. 행 수 불변(읽기 전용) 11. 다른 사용자 거래가 섞이지 않음. 12. 전략별: 매도 시점 적용 전략에 귀속(같은 주기 안에서 전략이 바뀐 뒤의 매도만 새 전략).
