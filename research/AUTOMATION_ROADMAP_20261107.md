> 지위: 지도 §13 자동화 단계표(들어가는/내려가는 조건)와 관측 계약(`OBSERVATION_CONTRACT_20261104.md`)을 뼈대로, **무엇을 어떤 순서로 만들고 무엇으로 검증하나**를 적는다. 조건을 완화하지 않는다. 모델 판정·점수 코드는 손대지 않고, 자동화는 **별도 모듈(`auto/`)** 로 만든다. 확정은 사용자, 구현 전 각 단계마다 사전등록(집행 규칙 동결) + 0-diff + 테스트.

## 2. 목표 구조 (만들 것 — `auto/` 모듈, 운영 코드와 분리)
```
[배치 20:10]  목록·배지·모의 계좌  ──▶  auto/plan.py   주문 계획서(계획ID·종목·수량·예상가·이유·보류 사유)   ──▶ docs/plan_YYYYMMDD.json + 텔레그램
                                            │ 게이트: 자료 신선도 · 산출 상태 · 장부 정합 · 한도 · 중복 계획 금지
[다음 거래일]  auto/execute.py  ──▶  (2단계) 사람이 증권사 앱에서 주문 → 체결 입력(PTW 또는 CSV)
                                     (2.5단계) KIS 모의투자 API 자동 주문
                                     (3단계) KIS 실계좌 API 자동 주문 — 한도·정지 규칙 안에서만
[장 마감 후]   auto/reconcile.py  ──▶  계획 vs 체결 vs 잔고 대조(종목·수량·금액·현금·미결제) → 불일치면 다음 계획 보류 + ⚠️
[매일]         auto/ledger.py     ──▶  돈 장부(원 단위, 1주, 잔돈, T+2, 비용 실측) · 상태기계(계획→수락→부분→완료/취소) · 감사 로그
```
- **계획과 집행을 떼어 놓는다**: 계획은 밤 배치가 만들고(결정적·재현 가능), 집행은 다음 날 별도 프로세스가 **계획 ID 로만** 한다. 같은 계획 ID 는 한 번만 집행(파일 잠금 + 원장 기록). 배치가 두 번 돌아도 계획은 하나.
- **주문 시각 규칙(사전등록 항목)**: 모델 가정 = t+1 **종가** 진입. 후보 ① 15:20~15:30 동시호가에 지정가(직전가) 주문 ② 15:00~15:19 시장가 ③ 다음 날 시가. 권장 ①(가정과 가장 가깝고 체결 확률 높음) — 2단계에서 체결가 vs 종가 차이를 실측해 비용 가정(0.5%)에 들어가는지 확인. 매도도 만기일 같은 시각.
- **수량 규칙**: 종목당 예산 = NAV/슬롯/목록 길이(소액 사다리 (a)~(c) 그대로) → 1주 내림, 호가 단위 반올림, 잔돈은 현금. 예산 < 1주면 그 종목 건너뜀(현금, 사유 기록).
