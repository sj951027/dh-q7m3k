## 1. 한 줄 결론
틀린 것의 대부분은 **지식이 틀린 게 아니라 '날짜가 붙은 약속'과 '상태를 적은 문장'이 흩어져 있어서** 생겼다. 세 장(결론·결정·함정)은 잘 지켜지고 있고(행↔정본 대조에서 고친 것 6행), 새는 곳은 그 바깥이다 — ① 기한이 지난 약속을 알려 주는 장치가 없다 ② 글로 적은 규칙은 두 번 넘게 어겨도 글로만 남는다 ③ 감시 장치가 사용자가 주로 일하는 저녁 시간에 꺼져 있다 ④ 세 장이 상한에 닿아 다음 결론을 넣을 자리가 없다.

## 4. 구조 제안 (승인 전 — 번호는 권하는 순서)
1. **기한 장부 한 장 + 시작 알림**: 날짜·조건이 붙은 약속(재질문·재측정·재현·판정문 병기·판정 예정)을 `DUE.md` 한 곳에 `기한 | 무엇 | 어디서 나온 약속 | 끝나면 어디를 고치나` 표로 모으고, 시작 알림이 "지난 것·7일 안"을 띄운다. `DECISIONS.md` §B(결정 대기)와 '고정 일정'을 이 장으로 옮기면 결정 장부에 약 5KB 가 비고(2-5), 흩어진 약속(2-3)이 한 곳에서 관리된다. 모델을 판정할 때는 그 모델 이름이 든 줄을 전부 확인하는 것이 절차가 된다.
2. **감시 장치를 저녁에도**: 시작 알림은 배치 시간대에도 띄우되(읽기 + 상태 파일 1개), 첫 줄에 "지금 배치 시간대 · 오늘 배치 끝남/도는 중(로그 기준)"을 적는다. 끝 검사는 지금처럼 끈다. CLAUDE.md 의 시간 규칙에 "배치가 끝난 뒤"를 어떻게 볼지 한 줄(사용자 결정).
3. **세 번째 단계 = 장치가 막기**: 두 번 넘게 어긴 규칙은 hook 으로 올린다 — Bash 명령에 heredoc 으로 python 을 넘기면 막기 · `taskkill /IM python.exe` 막기. `.claude/settings.json` 에 PreToolUse 두 줄 + 시험.
4. **되돌아감·낡은 문구 테스트**: (가) '금지 문구' 목록(예: "첫 판정 가능 시점 ≈ 9월", "효과 확인됨·차이 없음")이 생성 코드와 `docs/` 에 없는지 (나) 등록 표에서 판정이 끝난 모델의 페이지에 "판정 전·검증 전"이 없는지. `tests/run_tests.py` 에 1파일.
5. **세 장 자리 만들기**(1번과 함께): `PITFALLS.md` 에서 CLAUDE.md 로 올라간 두 줄 삭제 · `KNOWLEDGE.md` 는 닫힌 자료 행(K38~K40)이나 가장 긴 행부터 보관소로.
6. **PTW 화면 확인을 저장소 규칙으로**: 로그인 없이 화면을 띄우는 하네스(가짜 API 응답)를 PTW 저장소에 두고, PTW `CLAUDE.md` 마무리에 "화면을 고친 날은 하네스로 렌더" 한 줄. 로컬 시험 계정을 써도 되는지는 사용자 결정.

하지 않기를 권하는 것: 세 장 상한을 올리는 것(매 세션 전부 읽는 비용이 늘고, 지금 문제는 크기가 아니라 '결정 대기'가 결정 장부에 섞여 있는 것) · 지도 §0 을 자동 생성하는 것(만들 값의 원천이 글이라 장치가 글보다 먼저 낡는다 — 1번이 같은 문제를 더 싸게 푼다).
