## 1. 주문 시각·방식 — "t+1 종가 매수" 가정을 어떻게 실제 주문으로 옮기나
**실측 ① (10년 DB, 10/30 `RESEARCH_pick_exec_hold_10y_20261030.md` B2)**: 과매도 바구니 40일 초과는 t+1 종가 · t+1 시가 · t+2 시가 · t+2 종가 진입이 **서로 다르지 않음**(닫음).
**실측 ② (실제 목록, 2026-06-02~09-03 앵커, 40일 수익 %, 2,000회 부트스트랩)**:

|---|---|---|---|---|---|
| v30 (61) | +3.14 [+1.02, +5.10] | +3.06 [+1.16, +4.98] | +3.22 [+1.11, +5.26] | +0.02 [−0.22, +0.27] | −0.06 [−0.56, +0.46] |
| lv_b (58) | +2.43 [+0.67, +4.19] | +2.31 [+0.50, +4.01] | +1.87 [+0.09, +3.63] | +0.16 [−0.08, +0.40] | −0.08 [−0.53, +0.37] |

- 추천일 종가 → 다음 날 시가 갭은 0 근처(목록이 밤에 공개돼도 다음 날 시가에 튀지 않음 — 소액이라 시장 영향 없음과 일치). 진입 시각은 수익에 중요하지 않다. 그러니 **체결 확실성과 모델 가정 일치**로 고른다.
**검색(사실)**: 코스피·코스닥 정규장 09:00~15:20, **종가 동시호가 15:20~15:30** 에 주문을 모아 **단일가**로 체결. 동시호가 구간엔 **지정가·시장가 모두 가능**(조건부지정가·최유리·IOC/FOK 는 불가, 증권사별 차이 있음).
**판단**: 동시호가에 **시장가** 주문을 내면 그날 종가(단일가)로 체결된다 — 모델 가정 "t+1 종가"와 **정확히 같은 가격**이고 미체결이 없다(상한가·정지 제외). 지정가(직전가)는 가격이 움직이면 미체결. → **권장 = 15:20~15:25 사이 시장가 주문(매수·만기 매도 모두)**. 2단계(사람 클릭)에서 체결가 − 종가 차이를 실측(소액이라 0에 가까울 것 — 추정). 단, KIS 시장가 주문은 호가 단위·단가 0 규칙 등 주의점이 있어(블로그) 2.5단계에서 모의투자로 먼저 확인.
- 대안 ③ 다음 날 시가(t+2 시가): 수익 같고, 밤 배치 뒤 아침 한 번에 주문 가능 — 운영은 더 쉬움(장 시작 전 예약 주문). 장중 PC 가동이 어렵다면 이게 차선. 다만 모델 가정과 하루 어긋남(기록상 '가정 차이' 각주 필요).

## 2. KIS 모의투자(2.5단계) — 쓸 수 있나
**검색(사실·블로그 혼재)**: 모의투자는 KIS 홈/MTS 에서 신청 → 모의계좌번호로 Open API 별도 신청(실전·모의 앱키 각각 발급). 모의투자 서버는 `openapivts.koreainvestment.com:29443`(튜토리얼; 공식 샘플은 `svr="vps"`). **호출 제한은 모의투자가 훨씬 낮음**(공식 샘플 README: "모의투자 계좌는 REST API 호출 제한이 낮습니다", EGW00201 = 초당 건수 초과; 블로그: 실전 ≈20건/초·모의 ≈1건/초). 접근 토큰은 **하루 유효·발급 1분 1회**(공식 README: 1분당 1회). 모의투자 기간은 **최대 3개월**(블로그 — 공식 확인 못 함, 갱신 가능 여부 확인 필요). Open API 이용기간 1년·만료 30일 전 갱신·3개월 미거래 시 자동 해지 가능(공식 안내). 국내주식 모의투자에서 **시장가(ORD_DVSN 01) 주문 예제**가 있으나 공식 명세로는 확인 못 함(해외는 지정가만이라는 기록).
**판단**: 2.5단계 리허설로 **쓸 만하다**. 우리 쓰임(하루 매수 1~20건·매도 1~20건, 잔고·체결 조회 몇 번)은 초당 1건 제한 안에 넉넉히 든다(주문 사이 1초 간격). 확인 항목 3: ① 사용자 계정에서 모의투자 신청 가능한지와 **기간(3개월?)·갱신**, ② 국내 시장가 주문이 모의투자에서 되는지(안 되면 동시호가 지정가 = 예상체결가 로 대체), ③ 토큰 캐시를 실전과 **분리**(파일 다른 이름 — 지금 `kis_token.json` 은 실전용).
- 주의(블로그): 모의투자 체결은 실제 호가 체결 시뮬레이션이라 **체결 지연·부분 체결은 실전과 다름** → 2.5단계는 "코드가 안전한가"의 시험이지 체결 품질의 증거가 아니다. 체결 품질은 2단계 사람 클릭 실측과 3단계 소액으로.

## 3. 운영 기반 — 집 PC vs 작은 서버
| 선택 | 장점 | 단점·위험 | 비용 |
|---|---|---|---|
| **① 집 PC 상시 가동**(지금 + 작업 스케줄러 + 배치 밖 감지) | 추가 비용 0 · 키가 집 안에만 · 지금 구조 그대로 | 재시작·절전·정전·네트워크(10/14 결손 1회 실측) · 장중 09:00~15:30 켜져 있어야 함 · 집을 비울 때 | 전기 |
| ② 작은 가상 서버(국내/해외 VPS) | 24시간·무인 · 전원 걱정 없음 | 키를 밖에 두는 부담 · 윈도우 배치(.bat)·DB 이전 작업 · 10/18 합의 "클라우드 이전부터 안 함" | 월 1~2만원대(**가격은 확인 못 함** — 검색 안 함) |
| ③ 혼합: 계획(밤 배치)은 집 PC, **집행만** 서버 | 이전 범위 최소(집행 모듈 + 계획서 파일) | 두 곳 동기화(계획서 전달 경로·시각 동기) | ②와 같음 |
**판단**: 2단계(사람 클릭)까지는 ① 로 충분 — 집행이 사람이라 PC 는 밤 배치만 돌면 된다(지금과 같음). **2.5단계부터 장중 집행이 생기므로** 그때 ③ 을 결정(집행 모듈만 옮기면 되게 처음부터 `auto/` 를 분리 설계). 그 전 보강: 절전 끄기·자동 로그인·작업 스케줄러 "놓친 작업 즉시 실행"·배치 밖 감지 확장(장중 집행 완료 표식).

## 5. 자리바꿈 정의 5항목(모의 계좌 주간 자리바꿈 백분위 — 10/30 worklog)
**실측**: `paper_engine.simulate` 1회 = 0.02초(되감기 60일) → 2,000회 × 6모델 ≈ 4분(10/30 추정 "시간 단위"는 과대 — 보충표 병합 전 추정). 되감기가 길어져도 1년치 ≈ 0.1초/회 → 2,000×6 ≈ 20분, 일요일 여유 안.
| 항목 | 권장 | 근거 |
|---|---|---|
| ① 무엇을 섞나 | 각 모델 점수 표의 **종목 이름표를 같은 시장 안 1:1 뒤섞기**(판정 자리바꿈과 같은 정의, 창 = 되감기 시작~오늘) | 판정(VERDICT_NOTE)과 같은 정의 → 두 숫자를 같은 뜻으로 읽을 수 있음 |
| ② 횟수·seed | **2,000회 · seed 20261012**(판정 정본과 같게) | 비용 4~20분이면 줄일 이유 없음 |
| ③ 실행 자리 | 일요일 20:00 `notify_weekly.py` **앞**에 별도 `paper_placebo.py`(결과 JSON → docs) — 배치 없는 날·실패해도 리캡은 돎 | 주간 리캡이 백분위를 읽게 |
| ④ 어느 계좌 | 기본 모델 계좌 6장(v30·lv_b·le_a·lv_e·sv_a·sv_b)만. 게이트·고정비율·스위치·반반은 같은 매핑을 적용하면 따라오지만 **표시는 안 함**(비교군 B0~B3 는 점수 없음 → 제외) | 변수 하나(모델 점수)만 뒤섞는 뜻을 지킴 |
| ⑤ 시총 5분위 감도 | **월 1회**(첫 일요일)만, 주간엔 생략 | 판정 자리바꿈에서 시총층 안 통과율이 훨씬 낮아(2.1%→0.05%) 뜻 있는 감도지만 매주는 과함 |
