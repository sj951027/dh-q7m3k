# 2026-09-21 — 시장 레짐이 멈춘 지수를 쓰던 문제 + 지수 테이블 자동 정정 (2026.09.19 · 평소 결과 0-diff)

## 그래서 뭐가 바뀌나
- **스크리너의 시장 레짐 분석**이 지수를 고를 때, 원 소스(FDR KS11/KQ11)가 우리 DB(`ohlcv.db market_daily`)보다 **뒤처져 있으면 DB 값을 쓴다.**
  둘이 같은 날까지 있으면 종전대로 FDR — 그래서 평소 결과는 한 글자도 안 바뀐다. 대체했을 때는 로그에 한 줄:
  `ℹ️ 지수 소스: ohlcv.db market_daily (~2026-09-21) — FDR 는 2026-09-17 에서 정지`.
- **지수 테이블(`market_series.py`)이 임시값을 스스로 바로잡는다**: 증분 실행 때 최근 7일을 다시 받아 덮어쓰되, **소스의 마지막 행만은 덮어쓰지 않는다.**
- 지수 값 정정: 8/27 KOSPI 6879.87→**6912.37** · KOSDAQ 834.39→**837.65**(20:10 에 받은 확정 전 값이 그대로 남아 있었음. 네이버·FDR 현재값과 일치). 9/17·9/18·9/21 은 KRX 값으로 확인.

## 왜
- 9/21 배치 로그: 레짐 분석이 `KOSPI: 6,724.34 (+0.09% vs 어제)` — 9/17 장중에 멈춘 값. 실제 9/21 종가는 7,007.72(KOSDAQ 821.67 vs 836.27).
  9/20 에 고친 것은 **지수 테이블을 채우는 쪽**뿐이었고, 스크리너 본체는 같은 죽은 소스를 **따로 직접** 읽고 있었다. 9/18·9/21 이틀 레짐 입력이 낡았다.
- 영향(코드 확인): 레짐 점수는 시장 전체에 같은 값이 더해지므로 **시장 안 종목 순위·리더보드·성적표 무영향**. 낡은 것은 화면·텔레그램의 레짐 수치와
  PTW 상단 국면 칩. 이번 구간은 정정 전후 레짐 분류가 같아(코스피 강세 0 · 코스닥 반등 −3) **점수 변화는 0** 이었다.
